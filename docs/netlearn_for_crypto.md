# NetLearn 对密码学教改项目的价值分析

## 一、核心结论（TL;DR）

- **两者是同一套架构的"学科迁移"**：NetLearn（408 考研）与闽江大学《基于领域RAG与多智能体协同的密码学"理论—实践"融合培养与智能督导体系研究》在顶层架构、技术栈、闭环逻辑上高度同构。密码学申报书（大概内容.md / 项目书）直接复用/复述了 NetLearn 的核心术语：**FrugalRAG、GOMARL、领域RAG底座、多智能体协同、伴随式成长画像、督导闭环**。
- **NetLearn 已是"跑起来"的蓝本**：后端（FastAPI + LangGraph 8-Agent + InMemory/numpy 向量）+ 前端（Vue3 + Vite）都已落地；密码学项目目前只有文档（申报书 docx + 2 个 Python 脚本 `build_docx.py`、`draw_figs.py`），**尚无任何系统代码**。
- **可直接复用**：NetLearn 的检索/编排/督导代码可整体迁移，只需把"408 四科知识库"换成"密码学语料库"，其余工程底座几乎照搬。
- **必须改造**：密码学领域的特点是公式密集（LaTeX/MathML）、协议时序图、国密标准合规审查——这些是 NetLearn 没有的，需要新增；NetLearn 已踩过的坑（凭证暴露、单进程、冷启动、降级检索）务必在新项目里直接规避。

## 三、可直接复用的 NetLearn 资产（具体文件 / 模块）

- **检索层**：`frugal_rag.py`（混合检索 + BM25 降级守卫 `_degraded`）→ 直接适配密码学语料即可。
- **向量库**：已 seed 2083 条真实向量（E5/768，本地离线）；新项目需替换为国密/标准/推导树语料重新建库。
- **多智能体编排**：LangGraph 的 8-Agent 调度 + GOMARL 共识机制可裁剪为 4 个 Agent。
- **督导闭环**：能力画像、预警阈值、成长曲线逻辑可复用并扩展为"五维量表 + Git 提交分析"。
- **工程保障产物**：上一轮已产出的代码审查、事故响应、运维手册、部署检查清单（`deliverables/engineering-assurance/`）可作为新项目质量基线；对应的"agent-browser / expert-manager / skill 沉淀"流程可直接迁移。
- **安全审计清单**：NetLearn 已暴露并收敛的 P0/P1 风险（roleplay 跨用户隔离、密钥 URL 暴露、会话 TTL）应作为新项目的"预置红线"，避免重蹈覆辙。

## 四、必须新增 / 改造的点（NetLearn 没有覆盖）

1. **公式与协议多模态处理**：密码学是公式密集型（LaTeX/MathML、协议时序图）。申报书已规划"多粒度切块 + 混合检索"，但 NetLearn 是章节模板切块——需新增 **公式感知分块** 与 **符号归一**（如把 `\mathbb{Z}_p` 与 `Zp` 对齐），否则检索会失准。
2. **对抗性代码漏洞挖掘**：新项目的"代码工程 Agent + 对抗性漏洞挖掘"是新增诉求。NetLearn 的审计偏静态合规，需补"密码学侧信道/逻辑漏洞"对抗测试模块。
3. **五维成长画像 + Git 数据流**：NetLearn 画像较轻量；新项目要汇聚 Git 提交、推导步骤、周报等多源数据，需要额外的数据采集与特征工程管线。
4. **领域合规审查**：国密 SM2/SM3/SM4/SM9 的合规判据（GM/T 标准）需作为检索与评分的权威依据，类似 NetLearn 的"真实 E5 证据链"。

## 五、风险规避（沿用 NetLearn 教训）

- **不要重复踩坑**：NetLearn 的 `accessKeySecret` 明文拼 URL（讯飞要求，已成残留风险）、单进程单点+30s 冷启动、E5 不可用时的 BM25 降级——新项目应在设计期就用环境变量/密钥隔离 + 多实例/异步加载规避。
- **环境可复现**：NetLearn 的 `.venv / models / vectordb` 不持久化导致评测无法复现；新项目从第一天起就把语料与向量库纳入版本外但可重建（如 `build` 脚本 + 配置化 seed）。

## 六、建议的迁移路径（里程碑）

1. **M1 架构对齐**：把 NetLearn 的 FastAPI + LangGraph + FrugalRAG 拉到新项目，跑通"检索→出题/诊断"最小闭环（先用 408 替换成 GM/T 标准样例）。
2. **M2 领域语料**：整理 GM/T 系列、ISO/NIST、课程大纲（《应用密码学》大纲已就绪）、推导题库，建立可评测的检索基准（申报书已提"推导连贯性/规范符合率/防幻觉"三指标）。
3. **M3 角色裁剪**：把 8-Agent 收敛为 4 个领域 Agent；新增"对抗性漏洞挖掘"子能力。
4. **M4 督导闭环**：接入五维画像 + Git/周报数据采集，产出《研究生学术成长诊断报告》模板（申报书已设计）。
5. **M5 试点**：在《应用密码学》课程试点，对应申报书第三阶段（2027.7—2027.12）。
