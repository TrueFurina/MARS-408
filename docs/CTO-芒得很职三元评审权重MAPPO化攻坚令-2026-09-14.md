### 1.2 残酷真相（本攻坚的起点）

1. **`agent_weight_adjust` 输出的是规则版乘性因子**（basic→teacher×1.15；advanced→code_practice×1.10 + assessor×1.08；skip→各权重降），作用对象是**内容生成 Agent**（teacher/code_practice/assessor），**不是三元评审**（诚实/批评者/共识）。
2. **`agent_weight_adjust` 全库 0 处调用**——孤立接口，没有任何业务节点消费它。
3. **三元评审权重（诚实/批评者/共识）在代码里完全不存在**——共识合成是 LLM 精炼，评审门判定是固定阈值，无任何加权概念。
4. `review_intensity` 仅在 `agents/state.py` 注释中出现，无实际消费方。

**结论：对话里说过的"MAPPO 调三元权重"是声称；本篇把它变成可执行方案。**

## 2. 总体架构（评审权重 MAPPO 化）

```
学生回答/产物
   │
   ▼
┌──────────────────────────────────────────────┐
│ 三元评审链路（现有）                          │
│  诚实 Agent（evidence_check）→ 证据可信度     │
│  批评者 Agent（critic）→ 批评置信度           │
│  共识 Agent（agent_debate）→ 共识内容         │
└──────────────┬───────────────────────────────┘
               │ 插入点 A：加权共识合成
               ▼
┌──────────────────────────────────────────────┐
│ ★ review_policy（本攻坚新建）                 │
│  MDP：评审上下文状态 12 维                    │
│  动作：权重档位 5 选 1                        │
│  奖励：评审质量 + 成本 + 纪律                 │
│  训练：TeachingEnv 评审版 + PPO（复用 M3）    │
└──────────────┬───────────────────────────────┘
               │ 输出：三元权重向量 w=(w_h, w_c, w_k)
               ▼
┌──────────────────────────────────────────────┐
│ 插入点 B：评审门加权判定                       │
│  quality_gate：consistency_score×w + 共识×w   │
│  → PASS / RETRY（source 标记 mappo/rules）    │
└──────────────────────────────────────────────┘
```

**两个插入点，一处学习器，零侵入原评审逻辑**（权重不存在时退化为均匀权重=现状）。

## 3. 详细设计（执行者照此实现）

### 3.1 MDP 定义

**状态（12 维，评审上下文特征，确定性可复现）**

| # | 维度 | 来源（真实代码字段） | 归一化 |
|---|---|---|---|
| 1 | critic_confidence | `_critic_confidence(verdict, valid, invalid)` | 0-1 原值 |
| 2 | evidence_consistency | `evidence_report.consistency_score` | /100 |
| 3 | evidence_coverage | `evidence_report` 覆盖条目数 | /期望值 |
| 4 | consensus_status | `consensus.status`（pass/conflict/none → 0/1/2） | 序数/2 |
| 5 | gate_retry_count | `state.gate_retry_count` | clamp /3 |
| 6 | disagreement_level | 辩论轮数 / 各 agent 输出差异代理 | 0-1 |
| 7 | valid_critic_count | critic 有效质疑数 | /5 |
| 8 | invalid_critic_count | critic 无效质疑数 | /5 |
| 9 | quality_delta | 本轮 vs 上轮 consistency 差 | clamp -1..1 |
| 10 | cost_ratio | 已消耗 token / 预算 | 0-1 |
| 11 | mode_encoding | 教学模式（coach/tutor/monitor 编码） | 0-1 |
| 12 | round_ratio | 当前轮 / max_rounds | 0-1 |

**动作（5 档离散，与 M3 离散动作风格一致，可复用离散动作头）**

| 动作 | 权重向量 (w_honest, w_critic, w_consensus) | 语义 |
|---|---|---|
| 0 trust_honest | (0.6, 0.2, 0.2) | 证据强时信诚实 Agent |
| 1 trust_critic | (0.2, 0.6, 0.2) | 批评质量高时信批评者（多挑错） |
| 2 trust_consensus | (0.2, 0.2, 0.6) | 共识分歧小信共识（保稳定） |
| 3 balanced | (1/3, 1/3, 1/3) | 默认均衡 |
| 4 skip_review | (0, 0, 0) + 直接 PASS | 省成本（纪律约束下才允许） |

**奖励（四分量，可复算，防捷径）**

```
r = w1·Δgate_quality      # 评审质量提升：返工后 consistency/通过判定改善（+）
  + w2·precision_bonus    # 精准评审：正确放行优质产物 +；错误放行（RETRY 后才发现问题）重罚
  - w3·cost_penalty       # 成本：本评审轮 token 归一化（-）
  - w4·skip_abuse         # 纪律：skip_review 连续 ≥2 次重罚（防"全 skip 省钱"捷径）
```

权重初值：w1=0.4, w2=0.35, w3=0.15, w4=0.10
**关键：w4 必须有**——M3 踩过"策略学高频动作捷径"的坑，评审场景的捷径是"一律 skip"。

### 3.2 网络与训练

- **复用** `engines/mappo_policy.py` 的 `_build_networks`（ActorNet 3 动作头 → 扩展 5 动作头；CriticNet 共享）
- **训练**：CTDE + GAE λ=0.95 + PPO clip=0.2，`TeachingEnv` 评审版（新增 `ReviewEnv`：模拟"评审动作 → 质量/成本"，与 M3 同风格）
- **warmup_with_rules**：用现有 `agent_weight_adjust` 规则（1.15/1.10/1.08）做监督预热——规则是安全起点，策略只能在其上改进
- **3-seed 实测**：seeds 1/42/2024，对比：
  - A: RL 评审权重（本攻坚）
  - B: 固定规则（现有 agent_weight_adjust 规则版）
  - C: 监督学习权重（复现 A-HMAD 风格，离线回归到收集的决策标签）
  - 指标：评审质量 / 成本 / 精准率 / skip 频次

### 3.4 接线方案（两个插入点，零侵入）

**插入点 A：`engines/agent_debate.py::_final_consensus_refinement` 前**
- 读取 `state.get("review_weights")`；为空 → 保持现状（LLM 精炼）
- 非空 → 将各 Agent 的 `refined_content` 按权重加权注入精炼 prompt（或降级路径按权重加权拼接）
- `state["review_weight_source"] = "mappo"/"rules"` 写入供追溯

**插入点 B：`agents/quality_gate.py::quality_gate_node` 判定前**
- 加权：`effective_consistency = consistency_score × w_honest 相关项 + consensus 判定 × w_consensus + critic 质疑 × w_critic`
- 判定仍走现有 PASS/RETRY 逻辑（只换输入，不换门）
- fail-open 保留：任何异常 → 原逻辑

**灰度配置**（`config.get_gomarl_config()` 新增）：
```
use_review_mappo: bool = False   # 默认关，灰度开
review_min_review: int = 2       # 每会话至少 2 次真实评审（防 skip 捷径）
```

## 6. 风险与避坑（前人踩过的坑）

| 风险 | 后果 | 对策 |

| 与 P3③ 鲶鱼 MAPPO 化混淆 | 两个 MDP 混为一谈 | 本文档=评审权重（输出质量控制）；P3③=对抗模式（教学过程控制）。**先做本文档（novelty 主线），P3③ 后置** |

## 8. 本攻坚的最终定义（三位一体 · 2026-09-14 验收后修订）

> ⚠️ 本节原为"MAPPO 在线调权超一切"的单一卖点，经 2026-09-14 深度验收
> （`docs/CTO-深度验收结论与三项派单令-2026-09-14.md` §四）**修订为"三位一体"**：
> 在 effective 口径下解析式已占满头寸（capture 100%），"RL 超一切"是**可证伪的假话**。

**对外一句话（可直接引用）**：

> 我们的评审权重设计是**分层的**：① **解析式最优**——在可解析的 effective 口径下证明评审权重存在解析最优解
> （capture 100%、加噪 ±3% 下 99.8% 稳健），并已作为生产默认（`RULE_MODE = analytic`）；
> ② **RL 兜底复杂场景**——解析式失效的场景（字段缺失 / 目标非 effective / 强噪声）由 MAPPO 在线决策兜底，fail-open 降级；
> ③ **career 线 RL 真实增益**——鲶鱼对抗模式在真实特征空间由 MAPPO 学习，3-seed 真训 reward 全超规则版、
> 证据密度 0.41→0.55、纪律违规 0，这是**唯一有真实增益数据的 RL 环节**（合成环境：真实特征提取管线 + 合成上下文采样，非真实 trace；真实增益待 P5 试点）。

**披露纪律（写进一切对外材料）**：任何"MAPPO 调权"表述必须带**场景限定词**；
不得出现"RL 调权超一切""RL 优于现状/均匀权重"。数字一律以落盘 JSON 为准并注明"合成环境"。
