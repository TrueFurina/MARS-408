## 1. 不可复现缺陷：坐实与修复

### 1.1 实证（修复前）

```
career 同 seed 两次 warmup 权重 L2 delta = 110.69636376   → 完全不可复现
```

根因（与 review 侧同源）：

- `CareerModePolicy.__init__` **无 seed 参数、无播种** → 网络权重初始化走 torch 全局 RNG；
- `warmup_with_rules` 中 `rng = random.Random(seed)` **建而不用**（伪播种，与 review 侧一模一样）；
- `train_career_mappo.py:ppo_finetune` 用 `torch.multinomial` 采样，同样依赖未播种的 torch RNG，
  其中 `rng = random.Random(seed)` 亦为建而不用。

对比：原始模板 `engines/mappo_policy.py`（434/480 行）**有**正确的 `random.seed` + `torch.manual_seed`，
⇒ 是 career 复刻时漏掉的，不是设计选择。

### 1.2 修复内容

| 文件 | 改动 |
|---|---|
| `engines/career_policy.py` | 新增模块级 `_seed_all()`（python/numpy/torch 三路播种）；`CareerModePolicy.__init__` 增加 `seed: Optional[int] = 42` 并在建网前播种；删除 `warmup_with_rules` 伪播种行 |
| `experiments/train_career_mappo.py` | 删除 `ppo_finetune` 伪播种行 + 已失效的 `import random`，注释说明随机性由构造器统一播种 |

**为什么默认 `seed=42`**：训练脚本以 `CareerModePolicy()`（不传参）构造，默认播种才能让既有脚本不改即受益；
同时使 3-seed 之间共享同一初始化、仅环境 seed 不同 —— 正是"控制变量"想要的语义。

### 1.3 修复验证

```
career 同 seed 两次 warmup 权重 L2 delta = 0.0                 → 可复现 OK
脚本连跑两次：train 均为 {trained: True, mean_ep_reward: -0.314, mean_loss: -0.01288}
             seeds 完全一致                                     → 脚本级可复现 OK
pytest tests/test_career_policy.py test_career_modes.py test_career_p0.py → 46 passed
```

## 2. 旧 JSON 复检：数字有效，但 MAPPO 从未真验

`career_mappo_train_20260913.json`：

```
"train": {"trained": false, "reason": "torch unavailable"}
seed 1  rule -0.204  mappo -0.204   （逐位相同）
seed 42 rule -0.222  mappo -0.222
```

- 该次运行在**无 torch** 环境，`mappo` 分支整体走规则降级 ⇒ **rule 与 mappo 数字完全相同**；
- 因为网络从未参与，**初始化随机性没有机会污染数字** ⇒ 旧 JSON 作为"规则基线"是可信的，
  且其 `note` 字段已诚实标注"torch 不可用" ✓；
- 但反过来说：**career 的 MAPPO 能力从未在任何环境下被真实验证过**（直到本次）。

## 4. 更严重的问题（未修，需派单）：三模式决策从未激活

### 4.1 规则基线恒定 normal

```
CAREER_ACTIONS = ['normal', 'escalating', 'catfish']
seed 1    规则动作分布: {'normal': 1.0}
seed 42   规则动作分布: {'normal': 1.0}
seed 2024 规则动作分布: {'normal': 1.0}
seed 7    规则动作分布: {'normal': 1.0}
```

**四个 seed 全部 100% normal** ⇒ escalating / catfish 在全部合成实验中**从未被触发过一次**。
P3③「鲶鱼机制」作为对抗模式的核心卖点，在现有实验里没有产生过任何可观测行为。

### 4.2 根因：阈值不可达

`_rule_action_idx` 的判据 vs 环境实际特征范围（30 episode 采样）：

| 判据 | 阈值 | 特征实际范围 | 是否可达 |
|---|---|---|---|
| `catfish_ratio >= 1.0` | 1.0 | features[4] **min 0.0 / max 0.0** | ❌ 恒不满足 |
| `density < 0.35` | 0.35 | features[1] **min 0.500** | ❌ 恒不满足 |
| `density < 0.45` | 0.45 | features[1] **min 0.500** | ❌ 恒不满足 |

⇒ 三条分支全部不可达，函数恒 `return 0`。

### 4.3 附带发现：状态空间含 3 个常数维度

8 维状态的实测范围：

```
min : [0.000, 0.500, 0.500, 0.000, 0.000, 0.500, 0.300, 0.000]
max : [0.875, 0.785, 0.785, 0.000, 0.000, 0.500, 0.300, 0.875]
```

features[3]、[5]、[6] 恒为常数（0.0 / 0.5 / 0.3）⇒ **8 维里有 3 维零信息量**，
状态可分性进一步被压缩（与 review 侧"环境无可分性"是同类设计问题）。

## 5. 结论与建议（B 不擅自改 career 的规则/环境设计）

| # | 事项 | 状态 | 建议 |
|---|---|---|---|
| 1 | 不可复现缺陷 | ✅ 已修 + 已验证 | 合入；后续服务器真训才有意义 |
| 2 | 0913 旧 JSON | ⚠️ 有效但需注意 | 保留（torch unavailable 已诚实标注），但**不得表述为"MAPPO 已验证"** |
| 3 | 规则阈值不可达 | ❌ **未修** | **需 C/产品派单**：调整阈值或环境动态范围，使 escalating/catfish 可达；否则三模式决策是空转 |
| 4 | 3 个常数维度 | ❌ **未修** | 同 3，属环境设计；建议让 features[3]/[5]/[6] 携带真实信号或缩减状态维度 |
| 5 | 本次真训 passed=False | ℹ️ 如实记录 | 在 3 修复前，任何"mappo ≥ rule"的判定都无意义（两边都是恒定 normal） |

**B 的立场**：第 1 项合入；第 3/4 项必须由负责 career 实验设计的人（C）或 CTO 定夺 ——
调整阈值会让"mappo 与 rule 产生差异"，但这类改动必须由实验设计方背书，
否则容易被读成"为了让 RL 赢而调环境"。在修复前，**career 的 MAPPO 结论不具备对外表述价值**。
