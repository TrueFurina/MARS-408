## 1. 根因级缺陷：纪律护栏曾有 **6 处**复制实现

起初只发现 3 处；按"同类缺陷会连锁出现、且藏在回退链里"的教训做**全局排查**
（`grep -rn _block_skip`）后，实际是 **6 处**：

| # | 位置 | 形态 | 备注 |
|---|---|---|---|
| a | `ReviewWeightPolicy.select_action` | 内嵌闭包 `_block_skip` | 生产路径 |
| b | `evaluate_policy` | 内嵌闭包 `_apply_discipline` | 为"三方案统一"新增，实为第 2 份复制 |
| c | `engines/review_env_calibrated.py` | 模块级 `discipline_gate` | 注释自述"**逐字复刻**" |
| d | `experiments/diag_review_headroom.py` | `_block_skip` | 第 4 份，注释同样自述"逐字一致" |
| e | `scripts/verify_mappo_reachable.py` | `_guard` | 第 5 份 —— **我自己写的** |
| f | `scripts/verify_review_stage2_wrapup.py` | `guard` | 第 6 份 —— **我自己写的** |

> 教训：我上一轮刚批评角色 C"逐字复刻"，随后在自己写取证脚本时**又复刻了两份**。
> 仅靠"记得别复刻"是无效的；必须让复刻在结构上不可能 —— 即唯一实现 + 同一性断言。

**为什么要紧**：修 (a) 的差一（`>= SKIP_STREAK_LIMIT` → `>= SKIP_STREAK_LIMIT - 1`）时，
其余 5 处不会跟着改，只能靠"对拍测试"事后追。**代价已经真实出现过**：角色 C 的评测脚本
因绕开护栏，报出 `discipline_ok=False / max_skip_streak=2`，把"脚本口径错误"误诊为"策略违规"。

**处置（结构性，而非靠测试）**：

- 在 `engines/review_policy.py` 提升出模块级 **`discipline_gate(idx, features, skip_streak, reviews_done)`**
  作为**唯一真值实现**；
- (a)(b) 改为**委托**调用（不再复刻规则）；
- (c)(d)(e)(f) 改为**转发同一对象**（`is` 同一性），并保留原名字做别名以免破坏调用处；
- 新增**同一性断言**测试：`rc.discipline_gate is rp.discipline_gate`。
  —— 对拍只能"事后发现漂移"，同一性让漂移**无法发生**。

同时把精准判定也抽为唯一实现 **`review_precision(consistency, action)`**，
并由 `ReviewEnv` 通过 `env.last_precision` **对外暴露原生判定**，使评测脚本无需复刻阈值。

## 2. 三处口径事故

### 事故 1（本轮修）：精准率量纲漂移 —— 指标被静默清零

- `d55387e` 把 `consistency` 量纲由 0-100 改为 0-1；
- 而 `eval_review_mappo.py` 里有旧量纲残留：`thr = 75.0 if idx == 4 else 60.0`
  ⇒ 判定**恒为 False** ⇒ `precision_rate` 四臂全 `0.000`（此前为 `0.513`）；
- **全部单测仍是绿的** —— 典型的静默漂移。

**处置**：脚本改为读 `env.last_precision`（环境原生）。
**并加量纲哨兵**：`env_fingerprint()` 实测 `consistency` 区间与 precision 阈值并落盘
（实测 `[0.1504, 0.8999]`、阈值 `0.5`），量纲再变则新旧 JSON 指纹直接失配。

**重跑验证**：修正后重跑落盘 `review_mappo_eval_20260914_v2guarded.json`（**未覆盖** C 原件）——
`precision_rate` 由四臂全 `0.000` 恢复为**全 `1.000`**；`discipline_ok=True`、`max_skip_streak=1`。
同一份重跑也照出了诚实结果：在该**合成阶梯环境**里 `rl 10.460 < 最优恒定策略 balanced 10.837`
且 `rule 5.220 < supervised 5.384` ⇒ 该环境**不支持**"RL ≥ 规则 ≥ 监督"的验收结论
（CalibratedReviewEnv 才支持）。这正是"合成环境结论不可外推"的又一实证。

> 我在实现该指纹时**自己写错一次**：二分的更新方向写反（True 时抬 `lo`），
> 结果收敛到区间上界 `0.8999` 而非真阈值 `0.5`。已改为
> "True ⇒ `hi = mid`"并**加不变式断言**，写错即失败而非静默给错数。

### 事故 2（本轮修）：训练预算被静默饿死

`train_ppo` 改为批处理（默认 `batch_episodes=48`）后，**只传 `episodes` 不传 `batch_episodes`**
的调用方，真实梯度更新次数暴跌：`episodes=200` → **5 次**；`episodes=60` → **2 次**。
C 的评测脚本正属此类 ⇒ 结论"RL 不如 uniform"是**欠训练伪影**。
另外其 `stats["ppo"]` 读的是 `final_mean_return / first_mean_return`，
而这两个键在重构后**已不存在** ⇒ 落盘得到 `null`（静默丢失）。

**处置**：`eval_review_mappo.py` 补 `--ppo-batch`（默认 48）并**显式传参**；
落盘 `batch_episodes` / `n_updates`；键名对齐现行实现；新增
`MIN_VIABLE_UPDATES = 20` 硬门 + `training_budget_ok` 判决，
更新次数不足时**显式标注"该单元结论不可用"**（并说明这不是"RL 不行"的证据）；
CLI 默认由 `60` 上调为 `3000`（= 62 次更新）。

### 事故 3（本轮修）：评测脚本绕过生产纪律护栏

`eval_review_mappo.py` 对四臂**完全不施护栏**，规则臂直接调 `_rule_action_idx`
⇒ 报出 `discipline_ok=False` 假警报。

**处置**：四臂统一走 `discipline_gate`（生产唯一实现）。

## 5. 未决（须 CTO / 角色 C 决策，本轮不擅动）

1. **`precision` 分项零判别力**：在有效动作集 `{0,1,2,3}` 上该分量恒为 `+0.35`
   （对任何非 skip 动作恒判 True）⇒ 名义权重 0.35、实际不参与 argmax。
   若要让其生效，须建模"选错档位的代价"——**环境设计变更，需 CTO 书面背书**。
2. **`discipline` 分项恒不激活**：权重 0.10，仅在 `skip_streak ≥ SKIP_STREAK_LIMIT`
   时非零；而护栏的设计目标正是让该界线永不被跨过 ⇒ 护栏生效时恒为 0。
   属**设计使然**（"违规才激活"型惩罚），非失效 —— 已在审计输出中写清，避免被误读。
3. **环境内自造最优仍未消除**：唯一有判别力的 `gate` 分项由环境作者写死的档位判据决定
   ⇒ RL 的"赢"只等价于"更常命中该判据"。唯一出路是换到真实 trace（第 3 节 #5 的管线）。
4. **真实 trace 尚无来源**：生产侧未实现评审轨迹落盘（`api/audit.py` 是区块链审计日志，
   非评审轨迹）⇒ 阶段4 需业务侧先补齐 trace 落盘。
