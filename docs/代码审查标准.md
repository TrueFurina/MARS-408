# 代码审查标准（Code Review Standard）

> **定位**：本标准是 NetLearn / study-help-pro（MARS-408 与 芒得很职 双分支）所有 Pull Request 的人工审查依据。它建立在既有架构治理之上——**权威来源为 `docs/adr/*` 与 `CLAUDE.md`**；当通用最佳实践与本项目 ADR 冲突时，**以 ADR 为准**。
>
> **原则**：审查是"带教"，不是"设卡"。每条意见都要说清 **Why（为什么有问题）+ Suggestion（怎么改）**，而不是只丢一句"这里不行"。
>
> **优先级标记**：🔴 阻断（必须改，否则不予合并）｜🟡 应改（强烈建议，需理由豁免）｜💭 建议（nice-to-have）。

## 1. 通用质量维度（适用于所有语言/层）

### 1.1 正确性 🔴
- **契约不被破坏**：改公共函数签名/返回值/异常类型，须确认所有调用点（含测试）已同步；跨模块改动务必 `grep` 全仓。
- **边界与空值**：列表可能为空、dict 可能缺键、外部接口可能返回 `null`——不得无防御地下标/解包。
- **并发正确性**：共享可变状态（AgentState、缓存、向量库写）是否线程/协程安全？写路径是否唯一（见 §2.1 单写者）？
- **数值与量纲**：概率/分数/阈值是否与既有量纲一致（0–1 vs 0–100 是本项目真实踩过的坑，见 ADR-017）。

### 1.2 安全性 🔴
- **注入**：SQL/命令/LLM 指令注入——用户输入不得拼进查询或 shell；LLM 输入过 `shared/prompt_guard`。
- **XSS**：所有动态 HTML 经 DOMPurify；SVG 图标只来自 `components/icons.ts` 信任常量。
- **认证/授权**：受保护端点是否缺鉴权？权限判断是否可被越权？token 处理逻辑是否与时序攻击防护一致。
- **密钥**：任何密钥只从 `.env`/环境变量读；提交中不得出现明文密钥或 `.env`/`config.json` 含密钥字段。

### 1.3 可维护性 🟡
- **命名与意图**：函数/变量名表达意图；复杂分支有注释解释"为什么"而非"做什么"。
- **重复与抽象**：同一逻辑出现 ≥3 处应考虑抽取；但**判定语义的"抽取"必须是单一真值源**（见 §2.1），禁止"复制粘贴 + 事后对拍"。
- **魔法数字**：阈值/维度/迭代次数等用命名常量，并就近注释其来源与陷阱（如 `0.65` 余弦阈值、`768` 维度、`600_000` 迭代）。

### 1.4 性能 🟡
- **异步阻塞**：在 `async` 端点中调用同步重操作（E5 推理、TTS、PDF 解析、Redis 同步、python-pptx）必须用 `await asyncio.to_thread(...)` 或 `run_in_threadpool(...)`（CLAUDE.md 已列 6 处已知点）。
- **N+1 / 重复计算**：循环内重复检索/重复 embedding；可缓存的中间结果是否缓存。
- **大对象**：大响应/大文件是否流式或分块。

### 1.5 测试与可验证性 🟡
- **关键路径有测试**：业务逻辑、判定语义、安全护栏必须有对应用例。
- **变异验证**：关键测试要"杀得死变异体"——故意改回错误行为，测试必须 FAIL；杀不死的测试是摆设。
- **skip 必须有可审计理由**：`pytest.skip()` 理由要覆盖所有跳过路径并在调用处 `-rs` 可见；"没测"不允许伪装成"测过了"绿灯。
- **断言真实**：避免"只要不抛异常就算过"的弱断言；对拍类测试断言**行为一致**（最好用函数对象同一性，见 ADR-017）。

## 2. 本项目专属红线（按模块，最重要）

### 2.1 后端红线（命中即 🔴，除非 ADR/CLAUDE 明确许可）

1. **Embedding 硬约束**：检索层必须用 `intfloat/e5-base-v2`、维度 `768`、路径 `models/e5-base-v2`。**改回 MiniLM/384 会导致检索静默归零（历史事故）**。审查时 grep `sentence-transformers`/MiniLM 出现即拦。
2. **单写者约束（ADR-007/008）**：`uvicorn` 必须 `--workers 1`；导入队列 `services/import_worker.py` 进程内串行。任何引入"第二向量库写者"或"多进程写"的改动（含 career 线写 408 `vectordb`）一律拦截。
3. **LLM 通道策略（ADR-009）**：讯飞星火 X2 为第一优先级，DeepSeek 第二；**P0 不接 Qwen2.5**。改 `llm_provider.py` 通道优先级/回退逻辑须保持运行级三通道回退与指数退避。
4. **凭证管理（F-001）**：密钥只从 `.env`/环境变量加载；`save_config()` 自动剥离 `config.json` 密钥字段；生产 `AUTH_SECRET` 缺失必须 fail-fast。提交中不得出现 `.env`、`config.json`（含密钥）、`*.db`。
5. **安全中间件顺序**：`main.py` 注册顺序为 指标收集 → 安全响应头 → 请求体限制 → SPA fallback；生产 CSP `script-src 'self'`，仅 `/showcase` 降级。改注册顺序或放开 CSP 即拦。
6. **Prompt Guard 动词门控**：`shared/prompt_guard.py` 的 injection 正则须"动词门控"（只有 `instructions:` 后紧跟越权动词才触发）。**禁止退化为无动词匹配**（会误伤正常提问）。
7. **GOMARL 逗号切句**：`gomarl_conflict.py` 的 `_split_sentences_local` 必须在逗号处也切分，防"路由器在网络层，交换机在数据链路层"互补事实误报。改切句正则须用逗号分割单句测试防回退。
8. **认证密码学**：`user_store.py` PBKDF2 迭代 `600_000`；**防时序枚举的 dummy hash 必须匹配相同迭代数**。
9. **错误处理**：禁止 `except Exception: pass` 无声吞错；至少 `logger.debug/warning`，关键路径（向量搜索、RAG 检索、Agent 评分落库）须 `warning` 级。
10. **Quality Gate 语义**：为 fail-open（教学优先保障交付），但 `quality_gate REJECT → END` 为硬性阻断，不得软化。
11. **判定语义单一真值源（ADR-017）**：`discipline_gate` / `review_precision` 只允许一份实现（在 `engines/review_policy.py`）。**评测/诊断/影子探针脚本必须委托调用，禁止本地重定义**——这是本项目硬纪律，任何"新增诊断脚本须与生产同口径"违反即拦。
12. **数据库迁移幂等（D6）**：`db/migrations/runner.py` 迁移须幂等，已应用版本记 `applied.json`，lifespan 阶段执行且失败不阻塞启动。新增迁移须带版本号与回滚说明。
13. **生产/训练代码分离**：生产决策入口（`decide_review_weight`/`analytic_review_action`/`discipline_gate`/`review_precision`）必须为轻量、无 torch 依赖的单一真值源；重型训练代码（`ReviewWeightPolicy`/`train_ppo`/`ReviewEnv`/`warmup_with_rules`/`evaluate_policy`）应迁至 `experiments/`，不得与核心模块同文件（关注点分离，见审查示范 R2）。
14. **合成环境禁作效果宣称（诚信红线）**：本项目任何 RL/训练效果数字必须以 `engines/review_env_calibrated.py`（奖励复用生产 `weighted_consistency_score`）为准且先证同分布；`review_policy.py` 的 `ReviewEnv`/`train_ppo`（合成奖励阶梯）仅供历史对照，**禁止对外宣称或写入申报/参赛材料**（见审查示范 R1）。
15. **引擎内部维度同源（C1）**：`gomarl_mixer.py` 的 `GroupMixerNet.embed_dim` 等网络输入维度必须与 `AgentOutputEncoder`（E5，`config.dimension=768`）**同源派生**（`self._embed_dim = self.encoder.dim`），禁止写死与检索维度不符的死默认值（如 `384`）。死默认值会在训练权重缺失时被误当作"应改回"的目标，无提示地破坏形状匹配。
16. **文档宣称必须可达（C3）**：docstring / 申报书 / 前端文案宣称的能力必须有**实际可执行、可达的调用路径**。仅存在于 `if x is not None` 分支、但**从无调用方传入参数**的"死分支"，必须接通或在 docstring 显式标注"离线/实验能力，默认关"。禁止让"已实现"停留在不可达状态（本项目实例：`gomarl_conflict.py` 的语义级 E5 冲突检测因两条调用链均不传 `agent_embeddings` 而全程未执行）。
17. **跨模块访问走公开接口（C6）**：禁止跨模块直连私有下划线 API（如 `teaching_rules._dependencies` / `_agent_affinities` / `_match_chunk_to_topic`）；被复用的内部状态须由模块暴露公开访问方法（`get_dependency(topic_id)` / `iter_dependencies()` / `get_agent_affinity(name)` 等）。私有字段重构会静默改变调用点语义且不抛错。
18. **只读端点不挂 LLM 配额（C9）**：`require_llm_quota` 基于滑动窗口**计数**（`check_rate_limit` 内部 `incr`），只能挂在真正调用 LLM 的端点上。`/status`、`/neural-mixer`、`/teaching-rules` 等只读观测端点若挂载，会被监控/轮询持续扣减共享配额，最终 429 掉真实 LLM 调用。

### 2.2 前端红线（命中即 🔴）

1. **数据可溯源、禁合成兜底（CLAUDE.md 硬约束①）**：视图展示的每个量化数字必须来自后端真产物/真实接口；接口失败一律渲染空态（`—`/空态卡片），**不得回退示例值、合成值、上次已知值**；聚合数须同时展示 provenance（来源文件/产出时间/样本量/随机种子）。
2. **view 禁裸 `fetch`（硬约束②）**：所有 HTTP 走 `src/utils/api.ts`（统一 baseURL/鉴权/退避/友好错误）；组件层应只通过 composable 取数，不在组件内直接 `api.*`。
3. **缺失指标不许改口径硬凑（硬约束③）**：后端真产物不存在的指标（如原"矛盾检出数"）**不得用别的字段近似替代或沿用旧值**，只能删除或换成真存在的指标，并显式说明口径变更原因。
4. **XSS**：`v-html` 必须 `renderMarkdownSafe()` 或 `sanitizeSvg()`（DOMPurify）；SVG 图标只来自 `components/icons.ts` 信任常量。
5. **类型化**：`src/types/` 目录缺失是已知 P1 债（现存 `any` 约 353 处）。**新接口/新 store 必须建显式类型**；新增 `any` 须有理由；关键 `props`/`emits` 必须显式类型。
6. **视图粒度**：已有 `ResourceView`(1324 行)/`DashboardView`(1210 行) 为反面案例。**新代码避免单文件 >400 行**，有拆分价值的应拆 composable/子组件。
7. **账号体系一致性**：token 存 `localStorage` key=`mars408_token`，请求头 `Authorization: Bearer`；`LoginView.vue` 密码 `min_length` 须与后端（`auth.py` 后端 8）同步。

### 2.3 跨分支 / 仓库级红线

1. **双分支双身份（ADR-015）**：`main` = MARS-408（冻结基线，不动）；`career-literacy` = 芒得很职（活跃）。career 全部新增代码以 **`career_*` 前缀**沙箱化（`engines/career_policy.py`/`agents/career_nodes.py`/`api/career_training.py` prefix `/career`），**不改任何 408 源文件**。
2. **写路径隔离**：career 走独立 `db.career_store`，不写 408 `vectordb`/`netlearn_kb`（保 ADR-007 单写者）。
3. **唯一跨边界 = 只读复用 + fail-open**：如 `career_policy.py` 只读导入 `mappo_policy._build_networks`；跨边界调用不得引入写依赖。
4. **不提交敏感/大文件**：`config.json`/`.env`/`*.db` 不入仓；`.workbuddy/` 已 gitignore。
5. **并发会话安全**：多 AI 会话/多人并发编辑同一工作树时，提交前**只 `add` 自己的文件**，勿扫入他人改动。
6. **诚实红线（对外口径）**：career 鲶鱼默认规则版（`use_career_mappo=False`）；对外若标榜"神经网络智能"，须标"v1 规则原型"，不得默认暗示已启用 MAPPO（ADR-015）。

### 2.4 测试纪律（pytest 三环境病，命中即 🔴/🟡）

- 不可靠 `skip` 会伪装成绿灯：skip 理由必须可审计（`-rs` + 聚合进 skip 消息）。
- 关键测试需变异验证（故意改回错误必须 FAIL）。
- 权威回归看 Linux/CI；win32 跑真实向量/模型原生库会 SIGSEGV，**不要据此判代码错误**。
- 看 `passed/failed` 行判断成败，**别只看退出码**（pytest 三环境病之一）。

## 3. 反模式黑名单（来自本项目踩坑史，命中即 🔴）

| 反模式 | 现象 | 正确做法 |
|--------|------|----------|
| bash 反引号吞内容 | `python -c "...含反引号文本..."` 内容被命令替换吃掉，写入文件静默损坏 | 含反引号/反斜杠长文本一律写成脚本文件再执行 |
| heredoc 改写反斜杠 | Git Bash `cat <<EOF` 把 `\n` 当路径转换，落盘变 `try:/n` 致 SyntaxError | 用编辑工具写含反斜杠文本，不用 heredoc 搬运 |
| 过滤命令判成败 | `cmd \| grep -v "^ok"` 缓冲截断吞掉失败行，得"全绿"假象 | `cmd > out.txt 2>&1` 落盘后统计总数 |
| rmtree 误传父目录 | 生成器 `gen_x(path)` 内部先 `shutil.rmtree(path)`，误传父目录删光已入库产物 | 调任何带破坏性副作用的函数前先读函数体 |
| "已安装"≠"可用" | `import` 成功但底层原生库加载失败（如 pybind 命名空间） | 关键依赖做真实初始化探测 |
| 跳过理由不可见=无证据 | CI 日志只剩"3 skipped"，看不出为何跳 | skip 理由聚合进消息 + 调用处 `-rs` |
| 同类缺陷藏回退链 | 修 A 后端，回退链里 B 后端同因失效 | 修一处后必须再跑一次 CI |
| 私有 API 耦合 | 跨模块直连 `module._private` 内部字段/方法 | 为被复用的内部状态提供公开访问方法（C6） |
| 子串判定状态 | `"需人工审核" in x` 之类字符串包含做状态/计数判定 | 定义枚举/常量做精确判定（C4） |
| 贪婪 JSON 提取 | `re.search('{.*}', reply, DOTALL)` 贪婪匹配误抓正文最外层大括号 | 用平衡括号 / 代码围栏感知的提取器（C5） |
| 文档宣称死分支 | docstring 宣称的能力在 API/管线路径不可达 | 接通，或显式标注"离线/实验"（C3） |
| 死默认值 | 内部维度/阈值默认值与单一真源不符（如 `embed_dim=384`） | 从单一真源派生（C1） |

## 4. 分级审查清单（按改动类型给审查者速查）

**后端 agent / 引擎改动**
- [ ] 是否触碰 GOMARL 共识 / FrugalRAG 检索 / Quality Gate → 核对 §2.1 对应红线
- [ ] 是否新增/复用 LLM 通道 → 是否符合 ADR-009（X2 优先、P0 不接 Qwen）
- [ ] 是否引入新的同步重操作 → 是否 `to_thread` 包裹（§1.4）
- [ ] 是否改判定语义 → 是否委托 `review_policy` 单一实现（ADR-017）
- [ ] 新增/改动引擎端点 → 只读端点未误挂 LLM 配额（C9）；宣称能力是否有可达调用路径（C3）

**前端 view / composable 改动**
- [ ] 是否出现裸 `fetch` → 是否改走 `api.ts`（§2.2②）
- [ ] 展示数字是否来自真接口 → 失败是否空态、是否 provenance（§2.2①）

## 5. 审查意见写作规范

每条意见格式：

```
🔴/🟡/💭 **分类：简短标题**
位置：<文件>:<行号>
Why：<为什么是问题，最好带本项目依据（ADR/CLAUDE 条款或历史事故）>
Suggestion：<具体改法，给代码片段更好>
```

- **先给结论再列项**：PR 级结论用 ✅ Approve / 🔴 Request Changes / 💬 Comment。
- **区分阻断与建议**：任一 🔴 必须解决才能合并；🟡 可由作者说明理由豁免；💭 不阻塞。
- **教而不怼**：解释"为什么"，引用权威条款，给出可落地的改法。
