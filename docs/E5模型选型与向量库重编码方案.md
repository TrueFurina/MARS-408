# E5 模型选型与向量库重编码方案

> 关联：前几轮已修复「嵌入模型名被硬编码常量污染」的 P0（新增 `_effective_model_name()`，
> `/api/status`/`rag/status`/缓存元数据均改读 `config.embedding.model`）。本方案解决**残留的数据层错配**：
> 实机 2245 条向量是用 `multilingual-e5-base` 算的，而全链路其它证据指向 `e5-base-v2`。

## 1. 为什么要重编码（决策依据）

| 证据 | 指向的模型 |
|---|---|
| `train_mixer_real_v2.py` / `train_mixer_real.py` 加载 `SentenceTransformer('intfloat/e5-base-v2')` | **e5-base-v2** |
| `gomarl_mixer.py` 注释「config.dimension=768，e5-base-v2」 | **e5-base-v2** |
| 本地仓库 `netlearn_kb.json` 重编码余弦 +1.0000（v2）/ −0.0002（multilingual） | 本地库是 **e5-base-v2** |
| `experiments/results/benchmark_2026-10-08.json` 的 `e5_model: intfloat/e5-base-v2` | **e5-base-v2** |
| `config.py` DEFAULTS `embedding.model = multilingual-e5-base` | 默认是 multilingual（**偏离**） |
| 实机 2245 条向量按 multilingual 重算 | 实机是 multilingual（**偏离**） |

结论：**`e5-base-v2` 是项目真实意图模型**，multilingual 只是 config 默认值被沿用导致的漂移。
推荐把实机向量库重编码到 **e5-base-v2**，使「训练 / 本地库 / 基准 / 实机」四端一致。

> 若你基于中文语义召回质量另有考量要坚持 multilingual，只需把脚本 `--model` 与下方配置改回
> `intfloat/multilingual-e5-base` 即可，流程不变。

## 2. 两种运行模式（先确认，再选路径）

实机向量库可能两种模式之一，手段不同：

- **InMemory 模式**（最常见，vectordb_data 下有 `netlearn_kb.json` + `.emb.npy`）：
  `netlearn_kb.json` 即真值，**直接用 `scripts/reencode_kb_e5_base_v2.py` 重编码落盘文件**。
- **Milvus 模式**（`vector_db_mode == "milvus"`）：向量在 Milvus，`netlearn_kb.json` 仅作缓存。
  需改用 Milvus 端重写（删除集合 → 用目标模型重建），本脚本不适用，需另行按 `rebuild_vectordb.py` 走。

**确认命令（在服务器上）**：
```bash
ls -la vectordb_data/netlearn_kb.json vectordb_data/netlearn_kb.json.emb.npy
curl -s localhost:8002/api/status | python -m json.tool   # 看 vector_db_mode / embedding.model
```

## 3. InMemory 模式重编码步骤

> **推荐（省心且带硬保险）**：直接用 `py-server/scripts/reencode_remote_onetime.sh`。
> 它自动做 InMemory 模式检查 + 模型可用性检查 + 备份 + dry-run，**dry-run 后必须手敲 `YES`**
> 才做破坏性重编码；重编码完成后不自动重启，只打印「切配置 / 重启 / 核验 / 回滚」指令。
> 在你自己的 SSH 会话里：
> ```bash
> bash reencode_remote_onetime.sh            # PY_ROOT 默认=脚本所在 py-server 目录
> # 或：PY_ROOT=/opt/mangdehenzhi/py-server bash reencode_remote_onetime.sh
> ```

### 3.1 备份（必做，脚本内已有兜底，这里手动再做一次）
```bash
cp vectordb_data/netlearn_kb.json vectordb_data/netlearn_kb.json.pre_reencode.bak
cp vectordb_data/netlearn_kb.json.emb.npy vectordb_data/netlearn_kb.json.emb.npy.pre_reencode.bak
```

### 3.2 先 dry-run（不写盘，确认会真发生变化）
**前置检查（dry-run 之前）**：重编码脚本会把 `local_model_repo` 指到 `py-server/models/e5-base-v2`，
若该目录不存在会回退去 HuggingFace 下载。请先确认模型可用，避免中途失败：
```bash
ls -d py-server/models/e5-base-v2 2>/dev/null && echo "本地模型就绪" \
  || echo "需联网下载 intfloat/e5-base-v2（或无外网时先 scp 该模型目录到 py-server/models/e5-base-v2）"
```
```bash
cd py-server
python scripts/reencode_kb_e5_base_v2.py --dry-run
# 期望两行关键输出：
#   [info] 生效模型已确认=intfloat/e5-base-v2（补丁与导入顺序无关）
#   sample[0] cos(old,new) = 0.00xx  (≠1 表示模型已切换)
```

> **硬保险（fail-fast）**：脚本在加载 embedder 后会立即断言 `_effective_model_name() == 目标模型`，
> 不等则直接 `[FATAL]` 中止。这是因为 `db/embedder.py` 用 `from config import get_embedding_config`
> 在导入期绑死函数对象——若 embedder 被提前导入，patch 会静默失效、重编码拿回旧模型却不报错。
> 看到 `[FATAL] 模型补丁未生效` 说明环境异常，**不要**加参数硬跑，先排查。

### 3.3 正式重编码
```bash
python scripts/reencode_kb_e5_base_v2.py
# 脚本会自动再备一份 `<ts>` 时间戳备份，并同步覆写 .emb.npy 缓存
```

### 3.4 切配置 + 重启
编辑服务器上的 `config.json`（或环境变量）：
```json
"embedding": { "model": "intfloat/e5-base-v2", "dimension": 768 }
```
```bash
sudo systemctl restart mango-backend
# 或你实际的后端 service 名
```

### 3.5 核验
```bash
curl -s localhost:8002/api/status | python -m json.tool
# 期望：health.embedding.model == "intfloat/e5-base-v2"，embedding.loaded == true
```
检索质量核验（对齐此前 P0 验证口径）：用 `cn_01` 类查询做 top1 检索，
期望 `top1_score ≈ 0.94`（e5-base-v2 同模型 + 空缓存口径，参见
`项目平台云服务器选型与备案指南.md` §12.19 三档口径说明）。

## 4. 回滚

若重启后 `embedding.loaded=false` 或检索质量明显退化：
```bash
# 停后端 → 还原向量库 → 还原配置 → 重启
sudo systemctl stop mango-backend
cp vectordb_data/netlearn_kb.json.pre_reencode.bak vectordb_data/netlearn_kb.json
cp vectordb_data/netlearn_kb.json.emb.npy.pre_reencode.bak vectordb_data/netlearn_kb.json.emb.npy
# 配置 embedding.model 改回 multilingual-e5-base（若回滚到重编码前口径）
sudo systemctl start mango-backend
```

## 5. 安全红线

- 重编码**只改向量、不动 collection 名 / metadata / 业务逻辑**。
- 必须**先备份再写盘**；脚本已内置时间戳备份，但 3.1 的手动备份是最后兜底。
- 必须**同时覆写 `.emb.npy`**（否则 `_load` 优先读 .npy 用回旧向量，等于白做）。
- 重编码与切配置**不要跨重启拆开**：先重编码落盘 → 再切配置 → 一次重启生效。
- 生产数据操作，建议在低峰期、有人值守时执行。

## 6. 本仓库侧已完成的配套（无需服务器执行）

- `py-server/api/rag.py`：`rag/status` 的 `embedding_model` 改读 `get_embedding_config()`。
- `py-server/config.json`：`embedding` 段已显式声明（model + dimension），切换可见、安全。
