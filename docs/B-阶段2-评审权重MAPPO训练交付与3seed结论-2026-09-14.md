### 1.1 实现要点（对齐攻坚令 3.1/3.2/3.3）

- **状态**：12 维评审上下文（`review_state_features`），确定性可复算。
- **动作**：5 档离散权重 `REVIEW_ACTIONS = [trust_honest, trust_critic, trust_consensus, balanced, skip_review]`。
- **网络**：独立 ActorNet / CriticNet（**未改动** `engines/mappo_policy.py`，零侵入既有 648 基线）。
- **奖励**：4 分量 `gate 0.4 / precision 0.35 / cost 0.15 / discipline 0.10`。
- **学习**：`warmup_with_rules`（规则监督预热）→ `train_ppo`（CTDE + GAE + clip）。
- **协议入口**：`decide_review_weight(features, use_mappo, skip_streak, reviews_done)`；`use_mappo=False` → 均匀权重（= 现状，灰度安全）。
- **纪律硬约束**：`reviews_done < REVIEW_MIN_REVIEW(2)` 禁 skip；`skip_streak >= SKIP_STREAK_LIMIT(2)` 压回 balanced。
- **灰度**：`config.use_review_mappo()` 默认 `False`（本模块优先复用该单点访问器，避免两处读配置漂移）。

### 1.2 本轮修复的三处真缺陷

1. **输入 sanitize 缺失**：NaN/Inf 进线性层**不抛异常**，会静默产出任意权重，使"异常 → fail-open 均匀权重"
   的兜底形同虚设。新增 `_features_valid()`，在 `select_action` 与 `decide_review_weight` 两层拦截。
2. **训练不可复现（严重）**：`ReviewWeightPolicy.__init__` 完全不播种，网络初始化与 PPO 的 `dist.sample()`
   都走 torch 全局 RNG —— 同 seed 两次跑动作分布不同（实测 `balanced 1.000` vs `trust_honest 0.339`），
   **3-seed 实验事实上不可复算**。新增 `_seed_all()`（python/numpy/torch 三路播种）+ 构造参数 `seed=42`，
   并清理 `warmup_with_rules` 中 `rng = random.Random(seed); _ = rng` 的**伪播种**代码。
3. **灰度开关口径漂移**：`_mappo_enabled` 改为优先调用 `config.use_review_mappo()` 单点访问器。

## 2. 3-seed 实验结果（v2 可复现版，唯一真值源：JSON）

配置：`seeds=[7,42,2026]`、`episodes/cell=30`、`horizon=6`、`warmup_steps=300`、`ppo_episodes=60`、
`degraded=False`（torch 2.13.0+cpu **真训**）。

| 方案 | 回报(mean±std) | 质量增益 | 终态质量 | token | skip率 | 精准率 | 连发 |
|---|---|---|---|---|---|---|---|
| **uniform（=现状基线）** | **6.3627 ± 0.0702** | 16.839 | 66.84 | 5700.0 | 0.000 | 0.513 | 0 |
| rule（固定规则） | 5.3564 ± 0.0691 | 14.304 | 64.30 | 5596.1 | 0.000 | 0.513 | 0 |
| supervised（纯监督预热） | 5.4013 ± 0.0752 | 14.417 | 64.42 | 5600.0 | 0.000 | 0.513 | 0 |
| rl（warmup + PPO） | 5.7212 ± **0.5106** | 15.223 | 65.22 | 5633.3 | 0.000 | 0.513 | 0 |

**判据核对**

- `rl >= rule`：✅ True，增益 **+6.81%**（v1 曾报 +13.38%，作废）
- `rl >= uniform`（现状基线）：❌ **False，−10.08%**
- `rule >= supervised`：False
- 纪律：`discipline_ok=True`，`max_skip_streak_overall=0`
- **稳定性**：rl 标准差 0.5106 为 uniform(0.0702) 的 **7.3 倍** → 即使均值追平也不具备生产可用性

## 3. 根因诊断

### 3.1 动作分布：RL 近似克隆了固定规则

`python experiments/diag_review_action_dist.py`（train_seed=42 / eval_seed=999 / 30 episode）：

```
RL   分布 : {'trust_honest': 0.3389, 'balanced': 0.6611}
规则 分布 : {'trust_honest': 0.3278, 'balanced': 0.6722}
```

两者几乎重合 → **RL 学到的就是规则因子的克隆**，未产生超越规则的新策略。

### 3.2 决定性证据：恒定动作消融（收益上界）

`python experiments/eval_review_mappo.py --ablation --seeds 42`

| 恒定动作 | 回报 | 质量增益 | token | skip率 |
|---|---|---|---|---|
| 0 trust_honest | −0.0433 | 6.154 | 5400 | 0 |
| 1 trust_critic | 0.8851 | 8.413 | 6000 | 0 |
| 2 trust_consensus | 4.9113 | 14.228 | 4800 | 0 |
| **3 balanced（最优）** | **6.3784** | 16.898 | 5700 | 0 |
| 4 skip_review | **−9.6009** | −0.002 | 0 | 1.000 |

```
best_constant        : 3:balanced
best_constant_return : 6.3784294705618505
rl_return            : 5.424038193623875     (-14.96%)
rl_beats_best_constant: False
```

**结论**：最优策略就是**恒定 `balanced` = 现状均匀权重**。任何状态条件化策略的上界都不可能超过它，
因此**当前合成 `ReviewEnv` 下 MAPPO 化的理论收益空间为 0** —— 这不是训练不足或调参问题，是环境可分性问题。

### 3.3 PPO 微调：更新了权重，但行为空转且越训越差

参数差分诊断（warmup 50 步 + PPO 20 轮，seed=42）：

```
param L2 delta : 0.46448015      → 权重确实更新了（不是没跑）
improved       : False
mean_return_first_third : 5.4625  →  last_third : 4.9404   （下降）
```

消融中 `rl 5.4240` 与 `supervised 5.4240` **逐位相同**，说明 PPO 的权重更新**幅度不足以改变任何 argmax 动作**，
离散行为层面完全空转；同时训练回报曲线呈下降趋势（2.63~7.07 大幅震荡）。

三条线索互相印证：

1. **skip 动作被纪律约束完全封死**（`skip_rate=0`）→ 5 动作头实际仅 4 个可用，唯一能显著省成本的自由度消失；
2. **精准率四方案完全相同（0.513）** → `precision` 奖励项对动作不敏感，环境未建模"权重点错了会怎样"；
3. **质量增益无状态可分性** → 状态噪声下条件化权重与恒定权重的期望增益无显著差异，PPO 只能贴着 warmup 的先验走。

### 3.4 正面收获：纪律机制经验证有效（攻坚令风险项）

恒定 `skip_review` 策略回报 **−9.6009**（质量增益 −0.002）→ 证明"一律 skip 省 token"的捷径
**已被奖励重罚 + 纪律硬约束彻底封死**，该防线真实生效而非纸面设计。
3-seed 全量 `max_skip_streak_overall = 0`、`discipline_ok = True`。

## 4. 复现性修复为何使 v1 数字作废（重要）

v1（08:34 前落盘）与 v2 差异：

| 指标 | v1（未播种） | v2（可复现） |
|---|---|---|
| rl 3-seed 回报 | 6.0731 ± 0.1411 | **5.7212 ± 0.5106** |
| rl vs rule | +13.38% | **+6.81%** |
| rl vs uniform | −4.55% | **−10.08%** |
| 消融 rl vs 最优恒定 | 持平（逐位相同） | **−14.96%** |

v1 中"rl 回报与最优恒定动作逐位相同"纯属**未播种下的巧合**：每次进程的网络初始化不同，
恰好有一次收敛成恒定 balanced。**任何基于 v1 的结论都不可信，已全部重跑作废。**

修复后已验证：同 seed 连跑两次 `diag_review_action_dist.py`，动作分布逐位一致；
并新增防回归测试 `test_same_seed_training_is_reproducible` 与 `test_seed_all_covers_torch_rng`。

> **连带发现（未擅自修改，需 CTO 派单）**：同模板 `engines/career_policy.py` 存在**同样的未播种缺陷**
> ——其策略 `__init__` 无播种、`warmup` 中同样是 `rng = random.Random(seed)` 伪播种；
> 而原始模板 `engines/mappo_policy.py`（434/480 行）**有**正确的 `random.seed` + `torch.manual_seed`。
> ⇒ **career 线 `career_mappo_train_20260913.json` 的 3-seed 结果很可能同样不可复算**，建议优先复查。
