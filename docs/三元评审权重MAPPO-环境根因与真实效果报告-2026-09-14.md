# 三元评审权重 MAPPO · 环境根因诊断与真实效果报告

> 角色：C（实验数据）｜分支：`career-literacy`｜日期：2026-09-14
> 前置：`docs/三元评审权重MAPPO-影子探针效果报告-2026-09-14.md`（探针发现 RL 零效果）

## 0. TL;DR

1. **根因锁定**：原 `ReviewEnv`（HEAD 版）的**特征动力学退化**——12 维状态里 f1/f3/f9/f11 近乎恒定、
   f5/f10/f12 只是 step 的时间代理，轨迹是**一维单调漂移**。策略在训练分布上学到的映射无法迁移到真实
   特征空间 → **塌缩为恒定 balanced（= uniform 等价，零效果）**。已逐位复现：Δ = **−0.025**。
2. **改后有效**：换成**校准环境**（奖励直接复用生产同款 `weighted_consistency_score`，balanced 恒 0 增益）后，
   策略不再塌缩：Δ = **+1.636**（3 seed 全正，两次运行逐位可复现）。
3. **但结论仍是"不建议部署 RL"**：在**修正纪律口径后**（rule 臂此前未过纪律门，靠 12.1% 免费 skip 虚高 +1.0），
   真实效果排序是 **启发式(+2.998) > 规则(+2.139) > RL(+1.64~1.87) > 现状(+0.19≈无效果)**。
   RL 未能超过一条**一行代码的理论阈值启发式**。

## 1. 根因诊断（证据-first）

### 1.1 真实质量函数的解析结构

`agents/quality_gate.weighted_consistency_score` 展开后：

```
effective = s_h + (c − 1/3)·(s_c − s_h) + (k − 1/3)·(s_k − s_h)
```

- `s_h`：evidence 自评一致性（**可观测**，即 f2）
- `s_c`：`consensus.confidence_score × 100`（**不可观测**；f1 取自 `critic.confidence`，是另一个字段）
- `s_k`：`consensus.overall_score`，缺失时按 status 映射（**不可观测**；f4 只有 status）
- `balanced`(1/3,1/3,1/3) ⇒ Δ ≡ 0；`skip` ⇒ effective ≡ 100（**口径陷阱**，见 §4）

即：**最优动作由 (s_c−s_h, s_k−s_h) 决定**，而 12 维状态只携带 s_h。

### 1.2 真实空间的可挖头寸（240 条真实形态样本，同一纪律门口径）

| 口径 | 平均有效分 | Δ vs uniform |
|---|---|---|
| uniform（现状） | 66.809 | — |
| **mappo_current（线上共享策略）** | **66.997** | **+0.188（≈无效果）** |
| rule（规则基线，**已过纪律门**） | 68.948 | +2.139 |
| **heuristic_f2（单特征理论阈值 = 第 4 对照臂）** | **69.807** | **+2.998** |
| ORACLE（完全信息上界） | 72.275 | +5.466 |

- `balanced` 在 240 条样本中被 ORACLE 选中的次数 = **0 / 240**（即"躺平"永远不是最优）。
- oracle 动作分布：trust_honest 93 / trust_critic 71 / trust_consensus 76 / balanced 0。
- f2 与两个驱动量的皮尔逊相关 = **−0.727 / −0.822**（f1 仅 +0.021/+0.026 ≈ 0）。
- **可达成上限**：单特征阈值策略（train→test）**+3.215**，捕获头寸的 **60.2%**。

### 1.3 原环境的 bug（为什么学不动）

`HEAD:py-server/engines/review_policy.py` 的 `ReviewEnv`：

- `_features()` 里 f1 = `0.5±noise`、f3 = `0.5±noise`、f9 ≡ 0.5、f11 ≡ 0.5、f4 ≡ 0.0（`consensus_pass` 恒 True）；
  f5/f10/f12 = `step_count / 3 | horizon` → **纯时间代理**；
  真正变化的只有 f2/f6/f7，且同向单调漂移。
- 结果：训练分布是一个**一维轨迹**，真实特征是 12 维散布 → **策略在真实特征上落在分布外**。
- 实测复现（直接加载 HEAD 版模块训练，同超参）：

| seed | 在真实 240 样本上的动作分布 | mean effective | Δ vs uniform |
|---|---|---|---|
| 7 | `{balanced:238, trust_honest:2}` | 66.735 | −0.074 |
| 42 | `{balanced:240}` | 66.809 | +0.000 |
| 2026 | `{balanced:240}` | 66.809 | +0.000 |
| **3-seed 均值** | — | **66.785** | **−0.025** |

与首轮探针（14:43）观测到的 `mean effective = 66.785` **完全一致** → 根因确认，非偶发。

## 2. 校准环境（`engines/review_env_calibrated.py`）

设计原则：**做忠实模拟器，而不是"调参调到 RL 赢"**。

1. **奖励直接用生产函数复算**：`gate_after = weighted_consistency_score(evidence, consensus, w) − s_h`
   → balanced 严格恒为 0。"什么算好"由产品自身的质量函数定义，不存在第二套自造尺子。
2. **上下文分布对齐线上**：`(s_h, s_c, s_k, status, disagreement, budget…)` 按与线上同样的分布独立采样；
   12 维特征由真实 `review_state_features` 从合成 dict 生成 → 语义/量纲与线上一致。
   训练上下文与评测样本**独立抽样**（不同种子），无泄漏。
3. **纪律**：`discipline_gate` 逐字复刻 `review_policy.select_action` 内 `_block_skip`；
   本口径下 `reviews_done=0` ⇒ skip 恒禁用，且**记为无效动作给 −1.0**（防止策略白嫖纪律门兜底启发式）。
4. **可复现**：同 seed 逐位一致；`torch.set_num_threads(1)` + 确定性算法。

训练配置经小扫确定（判据 = held-out 400 条新上下文的头寸捕获率）：
`horizon=32, warmup=600, ppo_episodes=200, lr=3e-4, epochs=4` → 捕获率 42.3%（对比原配置 23.7%）。

## 3. 真实效果对照（改前 / 改后，同一 240 样本 + 同一纪律门）

| 训练环境 | 策略平均有效分 | Δ vs uniform | Δ vs rule | 动作分布 | 可复现 |
|---|---|---|---|---|---|
| **改前** HEAD 原环境（直接实测） | 66.785 | **−0.025** | −2.163 | 99%+ balanced | ✅ |
| 并行 Agent 新环境（工作区当前版） | 68.487 | +1.678 | −0.460 | — | 待核 |
| **改后** 校准环境（本交付） | **68.445** | **+1.636** | **−0.503** | `{balanced:92, honest:138, critic:10}` | ✅ 两次逐位一致 |

- 改前：**零/负效果**（塌缩）。改后：**+1.636**（60/240 样本改善，56.7%）。
- 但两类 RL 方案都**未超过 rule(+2.139)**，更未超过启发式(+2.998)。

## 4. 两个必须记录的口径缺陷（本轮修复）

### 4.1 探针此前对 rule 臂不公平（已修）

`observe()` 里 rule 直接取 `_rule_action_idx(...)`，**未过纪律门**，且当时 `reviews_done=0` 口径下
其它臂都被禁 skip。而 `skip ⇒ effective ≡ 100` 是质量函数的**满分通道**：rule 靠 **12.1% 免费 skip**
从 68.948 虚高到 **69.966（+1.018）**。首轮报告"rule 比影子高 3.18"部分是这么来的。
**已统一：所有臂走同一 `discipline_gate`**，并加回归测试 `test_rule_arm_is_discipline_gated`。

### 4.2 skip 是口径陷阱（必须锁死）

`weighted_consistency_score` 对全 0 权重返回 `effective = 100`（"不评审直接放行 = 满分"）。
若允许 skip，oracle 立刻变成"永远 skip"→ +33.19。**任何放开 skip 的对比都无意义**，
故所有结论都在 `reviews_done=0`（skip 禁用）口径下取得。

## 5. 关于并行改动（口径标注，非指责）

工作区 `py-server/engines/review_policy.py` 在本轮工作期间（16:07）被**另一并行 Agent** 重写
（+199/−95）：改成"每 episode 宽区间重采样 + 联合判据 `_true_best()`"。其代码注释自述：

> "真最优档位用**联合判据**……而生产规则是**级联判据**……两者**刻意不同源**……这是可学增益的真实来源。
> ⚠️ 诚实标注：该'联合结构'是本合成环境的建模假设，非实测结论。"

影响：该环境下"RL ≥ 规则"在**仿真中按构造成立**。因此：

- 它测得的 +1.678~1.869（本轮探针复测，真实质量函数口径）仍是**真数字**，但训练信号来自一个人为构造的判据，
  **不能作为"真实场景 RL 优于规则"的证据**。
- 本交付的校准环境**不引入任何自造判据**（奖励 = 生产函数），故 +1.636 是**无偏**的那一个。
- **建议 A/B 与 CTO 统一采用校准环境口径**，避免两套环境的数字混用。

## 6. 诚实边界（不确定性）

1. **所有头寸数字都依赖样本生成器的一个假设**：`s_h`、`s_c`、`s_k` 三者**相互独立**地均匀抽取。
   现实中三者大概率正相关（证据强的产物，批评者与共识分也高）。若相关，则
   `d_c = s_c − s_h`、`d_k = s_k − s_h` 的方差变小 → **头寸缩小、最优阈值随之改变**。
   ⇒ **绝对增益（+3.0 / +5.5）是暂定值；相对排序（启发式 > 规则 > RL > 现状）比绝对值更稳健。**
2. 样本生成器是"贴近真实形态"的合成数据，**不是真实日志回放**。要拿到可对外引用的结论，
   必须接真实评审轨迹。
3. 在线共享策略 `mappo_current` 在本快照中 = 三端等权 × `applied=false`（只做了规则预热，未真 PPO 化），
   其 +0.188 说明"当前部署形态"基本无效果。
4. 状态可观测性受限：`s_c`/`s_k` 不在状态里，**任何策略的天花板都被压住**（单特征阈值已吃满 60% 头寸上限）。

## 7. 结论与建议

**结论**：原环境的零效果不是"RL 不行"，而是**模拟器特征退化导致迁移失败**；校准后 RL 恢复正效果（+1.636），
但**仍不如既有规则，更远不如一条一行代码的阈值启发式**。

**建议（按性价比排序）**：

1. **优先把 `heuristic_f2` 折进规则**（`f2 > 0.675 → trust_honest`，否则 `trust_consensus`）。
   确定性、零训练、+2.998（头寸的 54.9%），且可解释、可审计。
2. **不要把 MAPPO 设为默认策略**（现状 +0.188；RL 最好 +1.87 < 规则 +2.139）。
3. **若要继续 RL 路线**，先解决状态可观测性：把 `s_c`（consensus.confidence_score）与
   `s_k`（overall_score）纳入状态，或明确接受"只能靠 f2"的天花板。
4. **修 `weighted_consistency_score` 的 skip 满分语义**：当前 `skip ⇒ 100` 使任何允许 skip 的评测失真。
5. **接真实日志回放**替换合成样本，再复算本报告全部数字。
