# ADR-009 — LLM 通道策略（两通道）

- **状态**：Accepted（已采纳，记录现有两通道实现）
- **日期**：2026-07-15
- **决策人**：架构师（architect）
- **相关**：纠正文档债 #3「三通道」口径漂移；`main.py:201` OpenAPI 描述已写「两通道」

## 背景

早期文档（README 技术栈、部分审计报告）将 LLM 通道描述为「DeepSeek / 讯飞星火 X2 / Qwen2.5 **三通道**自动回退」。实际代码与配置：

- `db/llm_provider.py` 三通道路由器在 Lite 版仅启用 **两通道**：讯飞星火 X2（主）+ DeepSeek（回退）。
- `main.py:201` 描述已为「DeepSeek / 讯飞星火 X2 两通道（P0 不接 Qwen2.5）」。
- Qwen / Tavily 仅在配置中预留（`config.json`），**未启用**；Lite 版拍板 **不接 Qwen**。

「三通道」表述与代码现实不符，易误导运维与评审。

## 决策

1. **权威口径 = 两通道**：讯飞星火 X2（primary）+ DeepSeek（fallback）。
2. **Qwen / Tavily 为配置预留项，非活跃通道**；若未来启用须在对应 ADR 中显式记录，并更新 `db/llm_provider.py` 与文档。
3. 所有对外文档（README 技术栈、PRD、审计报告）统一使用「两通道」表述，废弃「三通道」。

## 影响

- **文档**：README 技术栈「三通道」段落需改为两通道（列为后续 sweep，不在本轮节点数统一范围内）。
- **运维**：故障切换仅讯飞→DeepSeek 一条回退链；讯飞不可达时自动降 DeepSeek。
- **扩展性**：新增通道须走 ADR，禁止静默扩大通道枚举。

## 理由

- 单一稳定底座（讯飞 X2）是 Lite 版「稳定性」北极星（见 `docs/MARS-408_PRD_Lite_2026-07.md` G1）。
- 避免「三通道」虚假冗余带来的运维误判与评审质疑。
- 与代码（`main.py:201`、`db/llm_provider.py`）保持一致，消除文档/代码漂移。

## 备选方案（被否决）

- **保留三通道枚举但默认禁用 Qwen**：仍会造成「三通道」语义歧义，否决。
- **接入 Qwen 作第三通道**：Lite 版范围纪律禁止新增重型依赖，否决（v2 真版可重新评估）。
