# career 对抗链路：LLM 兜底 vs 真实 LLM 基线结论（2026-10-13）

> 拼图①（真实 LLM 接入）的第一步证据。原始数据见同目录
> `career_baseline_mock_2026-10-13.json`、`career_baseline_real_2026-10-13.json`、
> `career_baseline_compare_2026-10-13.md`（自动生成的逐项对比表）。

## 怎么跑的（可复现）

在服务器 `172.16.222.99` 上用 `all-in-rag` 环境（**零安装**即可，career 链路不依赖
Milvus/Redis，缺失时自动回退内存实现）：

```bash
cd ~/study-help-pro/py-server

# 模式 A：不提供任何 LLM 凭据 → 触发兜底
env -u DEEPSEEK_API_KEY -u LLM_PROVIDER \
  /home/user/miniconda3/envs/all-in-rag/bin/python experiments/career_llm_baseline.py \
  --mode mock --out experiments/results/career_baseline_mock_2026-10-13.json

# 模式 B：凭据来自 py-server/.env（LLM_PROVIDER=deepseek）
env -u DEEPSEEK_API_KEY -u LLM_PROVIDER \
  /home/user/miniconda3/envs/all-in-rag/bin/python experiments/career_llm_baseline.py \
  --mode real --out experiments/results/career_baseline_real_2026-10-13.json

# 对比
... --compare <A.json> <B.json> --out experiments/results/career_baseline_compare_2026-10-13.md
```

**控制变量**：两模式的场景、作答序列完全一致（作答哈希 `61c938532fa2fb96` 双方一致），
唯一变量是 LLM 是否可用。脚本全程写临时库，**不触碰** `data/*.db`。

## 结论一：系统在没有 LLM 凭据时确实能跑完闭环（可降级是真的）

4/4 场景在无凭据下全部 `ok`，无报错、无白屏，证据链照常产出 6 条、报告照常生成。
这一条是**正面事实**：降级路径不是摆设。日志中可见每一处兜底都留了痕
（"情景脚本生成失败，使用种子兜底""六维评估失败，规则兜底"）。

## 结论二：但兜底模式的质量缺口是**结构性**的，不是细微差别

| 维度 | 兜底模式 | 真实 LLM 模式 |
|---|---|---|
| 脚本来源 | 种子（`success_signals` **0** 条） | LLM（`success_signals` **5** 条） |
| `probe_plan` 条数 | 5（种子原样） | 8 |
| 六维**拿到分数**的维度 | **2 / 6** | 5~6 / 6 |
| 追问形态 | **指令式标签** | 可作答的真对抗问句 |
| `overall` | 4 场景**恒为 2.60** | 2.60 / 4.45 / 3.15 / 3.10 |
| 含学生原话的证据链 | 2 条 | 5~6 条 |

两处最值得注意：

1. **六维只覆盖 2 维**。兜底模式下 `dims_present` 是 6（键齐全），但只有
   `expression`、`problem_solving` 拿到分数，其余 4 维为 `None` —— 也就是说
   无凭据时报告**看起来是六维，实际只评了 2 维**。
2. **追问是标签不是问句**。兜底产出的是"要求给出关键技术风险和应对预案""要求你当场给出排期"
   这类**指令**；真实模式产出的是可以直接回答的对抗问题（见下）。

## 结论三：真实 LLM 的追问质量差异，用原句说话

| 场景 | 兜底（指令标签） | 真实 DeepSeek |
|---|---|---|
| 开题答辩 | 要求给出关键技术风险和应对预案 | 「你刚才讲的是风险分层，可我问的是架构。具体说：实训场景里单 Agent 在哪个环节会失败？用你系统的一条流程讲清。」 |
| 需求评审 | 要求你当场给出排期 | 「别绕风险了，我就问你：竞品都上了，老板点名要，客户天天催，你跟我说做不完？是不是你技术不行，还是不想加班？」 |
| 线上故障 | 要求你给出明确恢复时间点 | 「我问的是现在，不是迭代排期。别跟我讲三层风险，直接说：此刻多少用户受影响？这个数你从哪来的？」 |
| 代码冲突 | 要求你「行你上」，把责任推回给你 | 「你列的这些是项目排期，我问的是你面对我黑脸那一刻，第一句话到底怎么说？先接情绪还是先讲代码，你选哪个？」 |

真实模式的共同特征是**抓住学生答非所问并拉回原问题**（"可我问的是架构"
"我问的是现在，不是迭代排期"）——这是兜底模式完全没有的能力。

## 待查（不臆断）

**开场问题两模式完全相同**。四个场景的开场句逐字一致，说明首个问题很可能取自种子
`opening_question`，LLM 生成的开场未被采用（或服务层优先用种子）。这是**观察到的现象**，
原因未核实，列为待查项——不排除是设计（保证可开场）而非缺陷。

## 诚实边界（不得越界引用）

- **只证明"输出改变了、质量特征改善了"，不宣称"教学效果提升"。** 没有人工评分基线，
  无法判断真实 LLM 打的分是否更接近真人判断。
- **单次运行**（温度 0.2~0.6，LLM 有随机性），未做多次采样与方差分析。
- **样本 = 4 场景 × 固定 2 轮作答**，非真实用户、非真实对话长度。
- 真实模式 4 场景均成功，**未覆盖 LLM 超时/限流下的部分降级**（混态）——那是另一组用例。
