## 八、本次（2026-07-22）深度修改记录

### 8.1 重大 bug 修复：LangGraph 路由重试计数器失效（死循环）
- **现象**：向量库检索为空时，流水线在 `retriever ↔ planner` 之间**死循环**（首次冒烟 3m18s 未退出，日志反复"第0轮"）。
- **根因**：`graph.py` 的 `route_after_retriever` / `route_after_critic` 是 **LangGraph 路由函数（纯函数）**，在其中做 `state["regenerate_round"] = r+1` 的修改**不会持久化**；节点返回是唯一定态途径。计数永远为 0 → 永不达重试上限 → 死循环。
- **修复**：将自增逻辑分别移入 `retriever_node`（`agents/retriever.py`）与 `critic_node`（`agents/critic.py`）的返回值；`route_after_*` 改为只读 `regenerate_round`、仅做路由判定。
- **验证**：修复后冒烟节点序列为 `coordinator→diagnostician→planner→retriever→planner(重试1次)→retriever→generator_cluster→assessor→critic→path_planner`，检索空时正确重试一次即降级继续，**无死循环**。

### 8.2 环境修复：E5 embedding（torch）C 运行时损坏 → RAG 恢复
- **现象**：冒烟中 `import torch` 报 `c10.dll WinError 1114`，E5 嵌入模型加载失败 → 检索库空 → 生成降级（consensus=flagged、evidence=False）。
- **根因**：venv 原装 torch==2.13.0（Python 3.14 时代构建），与本机 Python 3.12 错配。
- **修复**：重装 `torch==2.7.1+cpu`（cp312 兼容），`c10.dll` 加载恢复正常，E5 768 维嵌入可推理。
- **验证**：重跑冒烟 `CONSENSUS_STATUS= passed SCORE= 3.95`（此前 flagged）、`EVIDENCE_PRESENT= True`（此前 False）、`retrieved_chunks` 非空、10 节点全跑通、`ERROR= None`、`total_time 288.7s`。

### 8.3 主题/依赖收尾
- `AssessmentView.vue` 雷达图渐变中点 `rgba(99, 102, 241)`（indigo 漂移）改品牌紫 `#7c6af2`，补全并行会话漏掉的带空格写法；`npm run build` ✓ 3.26s。
