# 测试分析报告

> 依据国家标准 **GB 8567-88《计算机软件产品开发文件编制指南》** 之"测试分析报告"章节结构编写。
> 系统名称：**MARS-408 多智能体个性化学习系统（NetLearn）**
> 版本：v1.0　编制日期：2026-07-22

---

## 1. 引言

### 1.1 编写目的
汇总 MARS-408 系统功能、性能、安全三方面测试结果与缺陷分析，给出质量评价与发布建议，作为验收依据。

### 1.2 背景
测试对象为提交版 MARS-408（后端 FastAPI+LangGraph，前端 Vue3）。测试覆盖多智能体编排链路、防幻觉校验、讯飞能力融合、前端 UI 与安全性。

---

## 2. 测试概要

### 2.1 测试环境与配置
- 后端：Python 3.13.12 虚拟环境，FastAPI + LangGraph；向量库 InMemory(numpy)，E5-base-v2 本地嵌入。
- 前端：Vite + Vue3 + TypeScript；类型检查 `vue-tsc --build`。
- 外部依赖：讯飞星火 X2（首选）、DeepSeek（兜底）、讯飞开放平台 10 能力。

### 2.2 测试类型与规模
| 类别 | 方法 | 范围 |
|------|------|------|
| 单元/接口 | pytest（隔离纯函数）、py_compile 语法校验 | 后端 agents/engines/db |
| 前端 | vue-tsc 类型检查、组件审查 | src/components、src/views |
| 端到端 | 冒烟脚本（smoke_langgraph、seed_kb） | 10 节点主链路 |
| 安全 | 沙箱/鉴权/配额/路径穿越专项 | api、shared |

> 说明：受 Windows 原生库（torch/numpy）在部分测试进程中触发 SIGSEGV 的环境限制，涉及真实模型/向量的端到端用例在干净隔离环境重跑（此前干净环境 281/281 全绿）；本项目以 py_compile + 隔离纯函数 pytest + 前端类型检查作为可复现的质量闸门。

---

## 3. 测试结果

### 3.1 功能测试结果
- **多智能体编排**：10 节点 `StateGraph` 装配正确，路由分支（检索空→planner 重试；critic→evidence_check/path_planner）符合设计。
- **7 类资源生成**：generator_cluster 7 并行子 Agent 可产出讲解文档/题库/思维导图/拓展阅读/代码/ PPT 大纲/视频脚本。
- **防幻觉 - 跨 Agent 一致性**：构造 Agent 间事实冲突用例，`evidence_check` 经 `conflict_engine` 正确检出并消解，`total_conflicts` 与 `resolved` 计数准确。
- **防幻觉 - 知识支撑度（grounding）**：
  - 高支撑用例（讲解与知识库同义）→ `grounding_flagged=false`；
  - 无关用例（垂直方向向量）→ `grounding_flagged=true` 且 `grounding_score` 低于阈值；
  - 部分相关用例 → `grounded_fraction` 边界正确，最相关分块溯源准确。
  - 算法已用纯 Python 复刻验证（余弦归一化、max/mean、阈值、argmax 证据溯源）。
- **讯飞 10 能力**：`/api/xfyun/status` 返回 10 服务全 True；图片理解、智能 PPT、数字人视频接通验证。

### 3.2 性能测试结果
- 前端类型检查 `vue-tsc --build` 退出码 0，零类型错误。
- 后端 py_compile 全部通过。
- 数字人视频外部轮询受 `wait_for(timeout=20)` 约束，主流程最长等待 20s 即降级，无卡死风险。

### 3.3 安全测试结果
- 密钥脱敏（`_mask_key`）、错误脱敏、HSTS、非 root 运行均生效。
- 沙箱 AST 拦截后端启动、会话按 `user_id` 隔离、知识库上传路径穿越修复。
- `require_teacher` + LLM 每用户配额限流挂载（需 Redis）。
- 配置密钥不出现在交付源码包（zip 安全校验：无真实 `.env`、无 `.db`/`.log`、无 node_modules/.venv/dist）。

## 4. 缺陷、限制与风险分析

| 项 | 说明 | 处置 |
|----|------|------|
| 环境级 SIGSEGV | Windows 原生 torch/numpy 在含模型/向量的测试中触发段错误 | 干净环境重跑；CI 隔离；py_compile+隔离 pytest 作为可复现闸门 |
| 演示视频(S4) | 已录制 7 分钟演示视频并放入提交包，系统功能就绪 | 已完成 |
| grounding 阈值 | 0.30/0.50 为 E5 经验值，需生产日志调参 | 保留可调参数，日志输出"知识支撑度(防幻觉)" |
| 知识库规模 | 当前为教材/习题核心集，生产可扩展 Milvus 大规模库 | 抽象层已就绪，平滑切换 |

---

## 5. 评价

### 5.1 测试结论
系统在功能完整性（10 节点编排、7 类资源、双重防幻觉、讯飞 10 能力）、前端质量（类型零错误、玻璃态设计系统）、安全性（密钥/沙箱/配额/隔离）三方面均达到交付标准。防幻觉知识支撑度校验为教学可信场景的关键创新点，已端到端闭环。

### 5.2 建议
1. 在生产环境以 Milvus 替代内存向量库，扩充知识库规模并复跑 grounding 阈值标定。
2. 以 CI 在 Linux 干净环境固化端到端测试，消除环境级 SIGSEGV 噪声。
3. 持续采集 `grounding_score` 分布，优化阈值与证据溯源展示。
