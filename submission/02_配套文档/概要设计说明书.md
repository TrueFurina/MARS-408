## 2. 总体设计

### 2.1 需求规定（摘要）
系统须实现：10 节点多智能体编排、7 类资源生成、跨 Agent 一致性 + 知识支撑度双重防幻觉、讯飞 10 能力多模态融合、408 四科知识图谱与学情画像、教师权限与配额限流。

### 2.2 运行环境
见《软件需求规格说明书》第 4 章。后端 `:8002`，前端 `:5173`。

### 2.3 基本设计概念与处理流程
采用**分层多智能体编排**思想：以 LangGraph `StateGraph` 作为控制流中枢，`AgentState` 贯穿全流程共享上下文（用户输入、画像、检索分块、生成产物、评估报告、视频文件等）。关键设计概念：

- **产物验收闸门（quality_gate）**：位于 `evidence_check` 之后，对不合格产物硬性阻断并触发重试，保证对外输出可被信。
- **冲突消解（conflict_engine）**：对 Agent 间事实冲突做自动裁决与回写。
- **降级优先（fail-soft）**：所有外部依赖（大模型、讯飞、向量库）均设兜底路径。

**主处理流程**：
```
coordinator → diagnostician → planner → retriever
   → generator_cluster(7 并行子Agent) → assessor → critic
   → evidence_check(一致性 + grounding) → quality_gate
   → [PASS] path_planner → END
   → [FIX]  generator_cluster (重试)
```

### 2.4 系统结构（模块划分）

| 层 | 模块 | 关键文件 | 职责 |
|----|------|----------|------|
| 编排层 | agents/graph.py | `create_agent_graph()` | 10 节点 StateGraph 装配与路由 |
| 智能体层 | agents/*.py | coordinator / diagnostician / planner / retriever / generator_cluster / assessor / critic / evidence_check / quality_gate / path_planner | 各节点业务逻辑 |
| 算法层 | engines/ | FrugalRAG(SFT+GRPO+ReAct)、GOMARL(NeuralMixer+冲突消解)、CARS 奖励塑形 | 检索增强与多智能体强化学习 |
| 知识层 | db/ | 向量库抽象（InMemory/Milvus）、E5 嵌入、知识图谱 | 知识检索与图谱 |
| 能力层 | db/xfyun_services.py | 讯飞 10 能力封装 | 图片/视频/PPT/搜索/纠错等 |
| 接口层 | api/ | FastAPI 路由（含 `/api/xfyun/*` 10 端点） | 前后端通信、鉴权、限流 |
| 前端 | src/ | Vue3 视图 + 组件 + 设计系统 | 交互与多模态呈现 |

## 3. 接口设计

### 3.1 用户接口
- 聊天式主交互（ChatView）：流式输出、Markdown 渲染、思考气泡、打字光标。
- 资源中心（ResourceView）：7 类资源卡片化呈现，分色语义标识。
- 证据校验面板（EvidenceCheckPanel）：一致性评分、防幻觉置信度半圆仪表、冲突修正 diff、知识库溯源。
- 讯飞 AI 工坊（XfyunWorkshop）：10 能力入口。

### 3.2 外部接口
- 后端 → 大模型：星火 X2（首选）/ DeepSeek（兜底）HTTPS API。
- 后端 → 讯飞开放平台：10 项能力 HTTPS/WebSocket 接口。
- 后端 → 向量库：InMemory（numpy）/ Milvus（生产）。

### 3.3 内部接口
- 节点间通过 `AgentState`（TypedDict）传递；路由函数 `route_after_retriever` / `route_after_critic` 决定分支。
- 前端 → 后端：`/api/*` REST/WebSocket，Vite 代理 `/api → :8002`。

## 4. 运行设计

### 4.1 运行模块组合
单进程后端（uvicorn `main:app --port 8002`，workers=1）；前端 Vite 开发或静态构建。文件锁 `vectordb_data/.import_writer.lock` 防止多实例写竞争。

### 4.2 运行控制
- 启动顺序：加载配置 → 加载向量库与 E5 → 挂载路由 → 监听。
- 重试控制：`regenerate_round` 由 `critic`/`retriever` 自增，路由函数只读不写，避免无限循环。
- 视频外部轮询：`asyncio.wait_for(..., timeout=20)` 包裹，超时降级。

### 4.3 运行时间
- 冷启动 ~30s；常规请求亚秒级（受大模型 API 延迟影响）。
- 数字人视频生成属异步长任务，主流程仅等待 ≤20s。

## 5. 系统数据结构设计

### 5.1 逻辑结构
- **AgentState**：贯穿全流程的共享上下文，含 `messages / profile / retrieved_chunks / resources / evidence_report / video_file / grounding` 等字段。
- **KnowledgeChunk**：`{text, embedding(768), group, source, score}`。
- **EvidenceReport**：`{status, consistency_score, confidence_score, total_conflicts, resolved, unresolved, conflicts[], corrections[], citations[], grounding_score, grounding_flagged, checked_agents[], course}`。

### 5.2 物理结构
- 向量库：开发期 `InMemoryVectorStore`（numpy 矩阵）；生产 `Milvus` 集合（768 维 IVF 索引）。
- 知识图谱：26 个 group 节点 + 边关系，前后端编号一致。

### 5.3 数据结构与程序关系
`retriever` 填充 `retrieved_chunks` → `generator_cluster` 消费并产出 `resources` → `evidence_check` 比对 `retrieved_chunks` 计算 `grounding` → `quality_gate` 依据 `evidence_report` 裁决。

## 6. 系统出错处理设计

### 6.1 出错信息
- 外部 API 超时/鉴权失败：记录结构化日志，触发降级。
- 幻觉检出：`EvidenceReport.grounding_flagged=true`，前端提示"检出疑似幻觉"。
- 安全事件：沙箱拦截、配额超限返回 429、密钥脱敏不出现在日志。

### 6.2 补救措施
- 大模型：星火 X2 → DeepSeek 兜底。
- 多模态：图片/视频/PPT 生成失败 → 降级提示，不阻塞主流程。
- 向量库：内存库缺失 → 走重建/降级。

### 6.3 系统维护设计
- 结构化日志 + Prometheus `/metrics` + 审计日志（AuditLogView）。
- Docker 非 root 运行、配置版本化迁移、自动化测试回归。
