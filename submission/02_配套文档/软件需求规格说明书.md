## 1. 引言

### 1.1 编写目的
本文档明确规定 MARS-408 系统的功能需求、性能需求、数据需求与运行环境，作为系统设计、开发、测试与验收的基线依据，供评审专家、开发团队与最终用户共同遵照。

### 1.2 背景
- **项目委托方/用户**：备考计算机统考 408（数据结构、计算机组成原理、操作系统、计算机网络）的考研学生。
- **开发方**：MARS-408 研发团队。
- **业务痛点**：408 四科知识体量大、抽象度高，通用大模型缺乏"学情诊断—个性化资源生成—可信校验—路径规划"的闭环；且大模型存在幻觉风险，不适合直接作为教学结论来源。
- **系统定位**：基于大模型的个性化资源生成与学习多智能体系统，覆盖"诊断→规划→检索→生成→评估→校验→验收→规划"的完整学习链路。

### 1.3 定义与缩写

## 2. 任务概述

### 2.1 目标
构建一个**可信、个性化、多模态**的 408 考研学习智能体系统：
1. 基于用户学情画像生成个性化学习路径与 7 类学习资源；
2. 通过多智能体编排与证据校验**抑制大模型幻觉**，保证教学结论可溯源；
3. 融合讯飞开放平台 10 项 AI 能力，提供图片生成、数字人视频、智能 PPT 等多模态输出。

### 2.2 用户特点
- 目标用户为计算机考研群体，具备基本计算机素养，但对四科深层原理掌握不均。
- 教师用户（teacher 角色）可进行知识库管理与审核。
- 系统需在交互上降低认知负荷，提供流式输出、Markdown 渲染与多模态卡片化呈现。

### 2.3 假定与约束
- **算力**：后端可调用讯飞星火 X2（首选）与 DeepSeek（兜底）大模型 API。
- **数据**：知识库覆盖 408 四科教材与习题；向量嵌入使用本地 E5-base-v2（768 维）。
- **运行约束**：单进程后端（文件锁防止多实例写竞争）；开发期使用内存向量库，生产切换 Milvus。

## 3. 需求规定

### 3.1 功能需求

#### 3.1.1 多智能体编排（核心链路）
系统后端以 **10 节点 LangGraph `StateGraph`** 编排，节点顺序与职责：

| 序号 | 节点 | 职责 |
|------|------|------|
| 1 | coordinator | 全局协调与意图识别 |
| 2 | diagnostician | 学情诊断（基于画像与历史） |
| 3 | planner | 任务规划（拆解学习目标） |
| 4 | retriever | 检索优化（FrugalRAG 召回） |
| 5 | generator_cluster | 资源生成集群（7 并行子 Agent） |
| 6 | assessor | 评估反馈（作答测评） |
| 7 | critic | 质量校验 |
| 8 | evidence_check | 证据校验（一致性 + 知识支撑度） |
| 9 | quality_gate | 产物验收闸门（硬性阻断不合格产物） |
| 10 | path_planner | 学习路径规划 |

**资源生成集群（7 并行子 Agent）**：讲解文档(Doc) / 练习题库(Quiz) / 思维导图(MindMap) / 拓展阅读(Extension) / 代码实操(CodePractice) / PPT 大纲(PPT) / 视频脚本(VideoScript)。

#### 3.1.2 个性化资源生成（7 类资源）
系统须能根据用户目标知识点生成以下 7 种资源类型：
1. 讲解文档　2. 练习题库　3. 思维导图　4. 拓展阅读　5. PPT 大纲　6. 代码实操案例　7. 审核报告。

#### 3.1.3 可信与防幻觉
- **跨 Agent 一致性校验**：`evidence_check` 节点调用冲突消解引擎，检出并消解 Agent 间事实冲突，输出 `EvidenceReport`。
- **知识支撑度校验（grounding）**：将生成的讲解文档逐句与检索到的知识库分块做 E5 余弦相似度比对；当支撑度 `score < 0.30` 或支撑句占比 `< 0.50` 时标记为疑似幻觉（`potential_hallucination`），报告含 `grounding_score` / `grounding_flagged` 字段与最相关分块溯源证据。
- 无 E5 环境时自动降级（`grounding=None`），不影响主链路。

#### 3.1.4 多模态与讯飞能力融合
融合讯飞开放平台 **10 项能力**：TTI 图片生成、图片理解、聚合搜索（万搜）、智能 PPT、数字人视频、文本纠错、公文校对、文本合规、星火角色模拟、智能简历。`generator_cluster` 在数字人视频就绪时调用 `generate_real_video` 写入 `state["video_file"]`，并受 `asyncio.wait_for(timeout=20)` 约束以避免阻塞主流程。

#### 3.1.5 知识图谱与学情画像
- 408 知识图谱按 group 编号分区：计网 1-7 / 数据结构 8-14 / 计组 15-21 / 操作系统 22-26（共 26 组，前后端编号一致）。
- 支持 8 维度学情画像与个性化路径推荐。

#### 3.1.6 用户与权限
- 支持普通用户与教师(teacher)角色；教师可管理知识库与审核资源。
- LLM 调用按用户配额限流；会话按 `user_id` 隔离。

### 3.2 性能需求
- 后端服务监听 `127.0.0.1:8002`；前端 Vite 开发服务 `5173`（生产构建静态托管）。
- 后端冷启动约 30s（加载向量库 + E5 嵌入），需以 `curl -m 30` 探活。
- 流式响应须呈现打字光标与渐显动效；单资源生成主流程对数字人视频外部轮询最长等待 20s。
- 向量检索在本地内存库下对 2000+ 条知识分块亚秒级返回。

### 3.3 输入 / 输出
- **输入**：用户自然语言学习目标、作答、上传图片/文档；教师审核操作。
- **输出**：7 类学习资源（Markdown/结构化 JSON）、证据校验报告、学习路径、多模态产物（图片/PPT/视频）。

### 3.4 数据管理
- 知识库：408 四科教材与习题，E5-base-v2 768 维向量化；开发期 `InMemoryVectorStore`(numpy)，生产 `Milvus`。
- 持久化：会话、画像、资源记录；密钥经脱敏仅存 `.env`（不入库、不提交）。

### 3.5 故障处理
- 检索为空 → `planner` 重试；质量不达标 → `critic` 路由至 `retriever`/`generator_cluster` 重试。
- 外部 API 失败 → 自动降级（DeepSeek 兜底、视频降级为脚本、PPT/图片降级提示）。
- 安全：沙箱 AST 拦截、密钥脱敏、错误脱敏、CORS 白名单、require_teacher。

### 3.6 其他需求
- 前端遵循玻璃态发光设计系统（v8/v9 令牌），双主题（深/浅），禁用硬编码色值与 emoji 图标。
- 全程可观测：结构化日志、Prometheus `/metrics`、审计日志。

## 4. 运行环境

### 4.1 设备
- 服务端：x86_64，建议 8 核 16G，具备稳定外网访问（调用大模型 API）。
- 客户端：现代浏览器（Chrome/Edge/Firefox 最新版）。

### 4.2 支持软件
- 后端：Python ≥ 3.12、FastAPI、LangGraph、NumPy、PyTorch(cpu)、E5 嵌入。
- 前端：Node.js ≥ 18、Vue 3、Vite、TypeScript。
- 生产向量库：Milvus（可选）。

### 4.3 接口
- 前端 ↔ 后端：REST/WebSocket（`/api/*`），Vite 代理 `/api → :8002`。
- 后端 ↔ 大模型/讯飞：HTTPS API（星火 X2 / DeepSeek / 讯飞开放平台 10 项）。

---

## 5. 验收标准
1. 端到端链路：输入学习目标 → 输出 ≥1 类个性化资源，且经 `quality_gate` 验收通过。
2. 防幻觉：在构造的冲突/无支撑用例下，`EvidenceReport` 能正确标记并溯源。
3. 多模态：讯飞 10 能力中至少图片理解、智能 PPT、数字人视频可演示；视频生成不阻塞主流程（≤20s 降级）。
4. 一致性：前后端知识图谱 group 编号 26 组完全一致；密钥不出现在交付包。
5. 文档：本文档及概要设计、测试分析报告齐全，结构符合 GB 8567-88。
