## 1. 取证闸门槛（引用护栏，工具内置）

`experiments/pilot_evidence_report.py`（位于 **`py-server/`** 下）的放行判据：

```
MIN_PILOT = { real_users: 5, finished_sessions: 10, max_bound_class: 3, finished_with_task: 5 }
```

- 退出码 **0** ⇒ 满足最低条件，可按 `pilot-design` 模板引用，**且必须连样本量 N 一起引用**；
- 退出码 **1** ⇒ 不构成成效证据，**不得引用任何条数**，只能写"尚未开展真实试用"。

闸看的是**账号身份 + 班级形态 + 任务关联**等结构性事实，不看总数——
所以"多跑几次测试"骗不过闸（见 `tests/test_pilot_evidence_report.py` 变异验证）。

> 2026-10-15 实测（本机库）：退出码 **1**，未满足项「单个班最多已绑定非测试学生 2 < 3」；
> 即使 `sessions_total=1178 / finished_real=254 / distinct_users_real=28` 这类大数，
> 闸依然判**不构成成效证据**——因为它看的是班级与账号形态，不是条数。口径照旧「尚未开展真实试用」。

## 2. 执行步骤（人 + 流程）

### 2.1 教师侧（拼图② 已打通，零后端改动）
1. 教师账号登录 `https://mangdehenzhi.app.workbuddy.host/` → 进入 **`/#/career/teacher`**（职业素养实训教师端），建 1 个班，导入真实学号花名册（R2）。
2. 创建任务 → 系统生成**任务码 + `task_id`**，锁定场景/难度/轮数。
3. 把任务码发给学生（群/邮件均可）。

> 2026-10-15 公网实测：该页 UI 完整 —— 「创建 / 导入花名册 / 发布任务 / 看板」全在，
> `/api/career/classes`、`/api/career/scenarios` 均 200，无控制台异常。

### 2.2 学生侧（前端 `CareerTrainingView.vue` "凭任务码加入"）
1. 学生**打开链接**（`https://mangdehenzhi.app.workbuddy.host/`）→ 点「立即注册」自助建号 → 输入任务码 → `POST /career/task/join`。
   （无需安装任何东西；账号必须是**线上注册**的，见 R2。）
2. 任务锁定场景/难度/轮数 → `session/start` **透传 `task_id`**（不带则看板恒空）。
3. 完成前测 1 场实训 → 系统自动出六维报告 + 提升路径（产品本身即干预）。
4. 间隔≥1 天后，再完成 1 场后测。

> 会话/轮次/证据/评估已自动落库（`career_sessions` / `career_dialogue_turns` / `career_assessments`）；
> 班级与花名册走教师端流程 ⇒ 使 `max_bound_class` 达标；任务码进入 ⇒ 使 `finished_with_task` 达标。
> 无需新表。

## 3. 报告写法（模板口径，强制）

- **样本量如实**：`N=<实际人数>`，标注"便利抽样、非随机"；
- **定性探索性**：用"探索性观察""初步迹象"，**禁用**"证明""显著提升"；
- **禁止**：显著性检验宣称、因果推断、百分比式成效（如"提升 30%"）；
- **允许且鼓励**：贴学生原话（可从 `career_dialogue_turns` 反查）、如实报告未完成者与失败案例、
  报告系统边界（兜底模式六维仅覆盖 2 维，见 `career_baseline_结论-2026-10-13.md`）。

## 4. 已知局限（必须写进报告）

1. 无对照组 ⇒ 不能排除练习效应；
2. 同场景/同难度 ⇒ 存在记忆效应；
3. 便利抽样（一个班）⇒ 不可外推总体；
4. 前后测均为系统自动评分，无人工基线 ⇒ 分数变化≠能力变化。
