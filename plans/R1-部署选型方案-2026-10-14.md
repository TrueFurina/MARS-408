## 2. 部署负载实测依据（均来自本仓库代码，非估算）

| 项 | 值 | 出处 |
|---|---|---|
| 后端框架 | FastAPI + LangGraph 11 节点 | README / CLAUDE.md |
| 嵌入模型 | **瘦包不含 E5**（剔除 sentence-transformers / torch，437MB 模型不入包）。实跑可启动：靠 `vectordb_data/e5_embed_cache.npz` 内容寻址缓存命中（启动日志 `InMemoryVectorStore 二进制缓存命中 2259 条 embeddings`）。⚠️ **缓存未命中**的新文本嵌入仍会回落 sentence-transformers——该路径**未验证** | 实跑 2026-10-14 |
| 向量库 | Milvus **可不装** → InMemoryVectorStore 自动回退 | CLAUDE.md:97 |
| 数据库 | PostgreSQL **可不装** → SQLite 自动回退 | CLAUDE.md:98 |
| 限流/熔断 | Redis 可不装 → 可降级为进程内滑动窗口（`RedisClient._local_rate_limit`），但**必须显式开 `RATE_LIMIT_ALLOW_LOCAL_FALLBACK=1`**：生产(STRICT)下**默认仍 fail-closed 拒绝**（CI 安全门禁 G2 固化的不变量——打掉 Redis 不能让限流失效）。⚠️ 本 VPS 不装 Redis ⇒ 该开关是**登录可用性的前提**，漏配则登录**第 1 次即 422**，见 §6/§7 | `py-server/db/redis_client.py` |
| LLM | DeepSeek API（外网 HTTPS 调用，不占本机算力） | CLAUDE.md 数据层 |
| 种子数据 | 2015 chunks + 230 题（2026-10-14 实测） | `import seed_data` 实测 |
| 试用并发 | 5 学生 / 10 会话（取证闸上限） | pilot-runbook |

**结论：单机可跑，无 GPU 需求，无外部中间件硬依赖**——Milvus/PG/Redis 全部走 fallback，
试用规模（5 人）下本地兜底完全够用。这直接决定主机规格下限。

**🔴 但有一条全局硬约束必须写进容量评估**：`vectordb_data/.import_writer.lock` 单写者锁
+ `--workers 1`（`app/lifespan._assert_single_worker()` 会主动拒启多进程）⇒
**同一时刻只能有 1 个后端实例，不能水平扩容**。故"5 人同时在线"必须按**单实例串行**
估算（对话/资源生成类端点本就偏慢），**不要按"加机器就能扛"来规划**。

|---|---|---|---|

## 4. 决策

**选 A：腾讯云轻量应用服务器 2C4G（Lighthouse），Ubuntu 22.04。**

理由：
1. **零外部依赖栈**（§2 实测）→ 2C4G/5M 带宽对 5 人试用是 3 倍以上余量；
2. 学生评估数据留在境内，合规路径最短；
3. IP:PORT 直连即可开跑，**备案与域名不作为试用前置**；
4. 生态同源（芒得很职静态站已用 workbuddy.host，后续可平滑迁移到统一域名）。

### 4.1 部署架构（单机全栈）

```
轻量 2C4G Ubuntu 22.04（公网 IP）
├── nginx          反代**整站**到后端（刻意不做静态托管，见下）
│   └── /          → 127.0.0.1:8000（后端已同源托管 SPA）
│   └── /api       → 127.0.0.1:8000（SSE 端点需 proxy_buffering off）
├── career-pilot   systemd 守护，非 root 用户，仅绑 loopback（不直接暴露 8000）
│   ├── 入口        /opt/career-pilot/venv/bin/python main.py（读 .env 的 HOST/PORT）
│   ├── 向量库      InMemoryVectorStore（不装 Milvus）
│   ├── 数据库      SQLite（不装 PG）
│   ├── 限流        进程内滑动窗口（不装 Redis；须 .env 开 RATE_LIMIT_ALLOW_LOCAL_FALLBACK=1）
│   └── 前端        <程序根>/site/（STATIC_DIR=site，与后端同根、CWD 无关）
└── .env           DEEPSEEK_API_KEY / AUTH_SECRET / ADMIN_PASSWORD / RATE_LIMIT_ALLOW_LOCAL_FALLBACK 等，chmod 600
```

> **为什么 nginx 不做静态托管**：后端 `app/static_sites.py:install_spa()` 已挂 `/assets`，
> 并对非 `/api` 的 404 **GET/HEAD** 回退 `index.html`。若再让 nginx 托管一遍前端，
> 会产生"谁先匹配"的诡异行为（典型症状：能打开首页但子路由 404，或资源 404）。
> **只反代，别双重托管。** 运行资产见 `deploy/vps/`。

### 4.2 上线步骤清单

1. 建机：轻量 2C4G / Ubuntu 22.04 / 系统盘 50G SSD / 带宽 5M；
2. 安全组：仅开 22（限本机 IP）与 80；**不要对外开放 8000**（后端只绑 loopback，由 nginx 进）；
3. 建用户与目录：`sudo useradd -r -s /usr/sbin/nologin career`；
   `sudo mkdir -p /opt/career-pilot && sudo chown -R career:career /opt/career-pilot`；
4. 生成部署包（**在开发机执行**）：`python scripts/build_career_pilot_package.py`
   —— 从 `py-server/` 同步生成 `deploy/career-pilot/backend/`，自带沙箱 `config.json` 覆盖
   （强制 `milvus/redis.enabled=false`）与瘦版 `requirements.txt`；`--check` 可验字节级无漂移且幂等。
   前端产物先建于 `backend/site/`：`npx vite build --config vite.deploy.config.ts`；
5. 传输：`rsync -a deploy/career-pilot/backend/ career@<IP>:/opt/career-pilot/backend/`
   （`.env` 单独 `scp` 后 `chmod 600`；`config.json` / `.env` / `vectordb_data` 均不入库，已被 `.gitignore` 封挡）；
6. 装依赖：`python3 -m venv /opt/career-pilot/venv && /opt/career-pilot/venv/bin/pip install -r requirements.txt`
   （**瘦依赖，不含 torch/E5**；若目标机 pip 出网受限，用 `uv pip install --system -r requirements.txt` 兜底）；
7. 配置 `.env`：`NETLEARN_ENV=production` / `HOST=127.0.0.1` / `PORT=8000` / `STATIC_DIR=site` /
   `AUTH_SECRET`(≥32) / `ADMIN_PASSWORD`(≥16) / `DEEPSEEK_API_KEY` /
   **`RATE_LIMIT_ALLOW_LOCAL_FALLBACK=1`**。
   ⚠️ **production 下 `AUTH_SECRET` 与 `ADMIN_PASSWORD` 缺一即拒启**（fail-fast，见 §6）；
   ⚠️ **漏配 `RATE_LIMIT_ALLOW_LOCAL_FALLBACK` ⇒ 本机不装 Redis ⇒ 限流 fail-closed ⇒ 登录第 1 次即 422**
   （这是**默认安全姿态**，不是 bug；本机设计上无 Redis，故显式放行降级，见 §7）；
8. 守护：安装 `deploy/vps/career-pilot.service` → `daemon-reload` → `enable --now`；
9. nginx：安装 `deploy/vps/nginx.conf` → `nginx -t` → `reload`；
10. 冒烟（GET/HEAD 均可，后端已补齐 HEAD）：
    `curl -s -o /dev/null -w '%{http_code}\n' http://<公网IP>/api/status` → 200 且 `status:"ok"`；
    `curl -sI http://<公网IP>/` → 200；随后用**真实浏览器**过一遍
    「教师建班 → 发任务码 → 学生凭码加入 → 多轮实训 → 六维报告 → 班级看板」；
11. 取证闸开跑：按 `pilot-runbook` 第三节记录 MIN_PILOT 五项指标（**未放行前不得引用任何条数**）。

## 6. 发布通道（腿①）现状与本 VPS 路线的关系（2026-10-14 18:4x 记）

**已实测跑通的准备（可复用）**：瘦包 `deploy/career-pilot/backend/`（68M，无 torch/E5）
在隔离 venv 下真实启动并对外服务——`GET /api/status` 200（`status:"ok"`）、
`GET|HEAD /` 200 且含 `<div id="app">`、真实哈希资源 `/assets/index-*.js` 200、
`GET|HEAD /api/status` 200、`openapi.json` 注册 12 条 `/career/*` 路由、
`production` 下 admin 登录 **200** 且**限流仍生效**（第 6 次起 422）。

**🔴 但发布动作被硬阻塞，未发布任何内容**：`workbuddy_sites_deploy` 返回
`sites_deploy_failed` / code **`SITES_ACCOUNT_MISMATCH`**（`retryable:false`）——
工具把该目录解析到应用 `wbapp_SCV2PQvaYZGxutFzKn3mwC`，而该应用**属于另一个账号**
（`genie-baas: application … does not belong to caller`）。行为规范明确要求：
**不得重试、不得换参数、不得换目录或新建应用绕过**，须**切回当初发布该应用的账号**后
再由用户明确要求发布。⇒ **本仓库任何目录的发布都受此账号归属约束**（`.genie` 的
`localDir` = 仓库根）。**本 VPS 路线不受此约束**（自建机 + rsync + systemd）。

**为什么 `production` 不再是障碍**：改造前在无 Redis 环境下 `REDIS_STRICT` 会让
`check_rate_limit` fail-closed 返回 `False` → `api/auth.py` 抛 ValidationError →
**登录一律 422**；且 production 会**跳过演示账户播种**（`lifespan` 生产分支），
双重锁死。现改为「Redis 不可用/异常 → 降级为**进程内**滑动窗口」后，
因部署被单写者锁硬约束为 `workers=1`，进程内计数即全局唯一计数，**与 Redis 语义等价**，
于是既保住防爆破、又恢复登录。生产模式同时保住另外四项硬化：
不播演示账户（`seed_demo_data` 的默认弱口令对，公网不应存在）、`CSP_PRODUCTION`、
CORS 仅显式白名单、`AUTH_SECRET`/`ADMIN_PASSWORD` 强制。

## 7. 限流降级改为「显式开光」——为何不是回退到故障态（2026-10-14 19:5x 记）

**变更**：上一轮曾把「生产 Redis 不可用 → fail-closed」**整体**改成「一律降级进程内窗口」，
结果撞了 **CI 安全门禁 G2**（`scripts/security_gate_assert.py::assert_g2_rate_limit_fail_closed`
要求 `check_rate_limit` 内存在守卫链含 `REDIS_STRICT` 的 `return False`）。
🔴 该脚本**不在本地 pre-commit 七道门禁内** ⇒ 本地全绿而 CI 红（引入点 `8a4cd51`，
经逐提交 **job 级**二分确认；注意 `ci.yml` 有 `cancel-in-progress`，**run 级 `cancelled`
会掩盖 job 级 `failure`，必须下钻**）。

**现在的形态**（同时满足两条已裁决项，非二选一）：
- 生产 + **未开**开关 → **fail-closed**（G2 不变量：攻击者打掉 Redis 不能让限流失效）；
- 生产 + **显式** `RATE_LIMIT_ALLOW_LOCAL_FALLBACK=1` → 进程内滑动窗口兜底；
- 非生产 → 自动降级，本地联调不受影响。

**行为级实证**（隔离副本 + 全新端口 5401 + 全新库，非仅 AST 通过）：
- 开关**关** → 登录**第 1 次即 422**，正文 `{"error":{"code":"VALIDATION_ERROR","message":"操作过于频繁，请稍后再试"}}`
  ⇒ fail-closed 落到行为上，不是只让门禁满意；
- 开关**开** → 登录 1~5 次 **200 带 token**、第 6 次 **422** ⇒ 修复生效**且限流仍强制**。

🧨 **踩坑**：验证「默认姿态」必须**换新端口 + 新库**。首轮用同一端口复测得到的一批 422
是**假证据**——`TaskStop` 只杀了包装进程、uvicorn 子进程存活，5399 上同时跑了两个实例，
那批 422 其实是**开关开着的实例**把 `login:user:admin` 桶打满后的表现（同桶、900s 窗口）。

⚠️ **本机 .env 已配 `RATE_LIMIT_ALLOW_LOCAL_FALLBACK=1`**（`.env` 不入库）；
`deploy/vps/career-pilot.service` 走 `EnvironmentFile` 读取，**建机时须一并写入该键**。
