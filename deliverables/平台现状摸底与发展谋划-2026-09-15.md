## 2. 风险研判（按紧迫度）

### 🔴 R1 · 91 个未提交文件悬空（最高优先）
- 现状：`git status` = 91 条目（68 在 `src/`，67 个 `.vue`）+ 7 docs / 6 deliverables / 4 py-server / …
- 归属：a11y、design-system、ADR-007 等**并发会话的 WIP**（交接文档 `待办交接-2026-09-15.md` §0/§2 已明令"不要动，等对应会话"）。
- 风险：① 误 `git checkout` / 并行 merge 会互踩（历史已发生一次，`3d40092` 恢复）→ 0 丢失但费时；② 磁盘/会话异常会静默丢失；③ 你无法一眼判断"哪些已做完、哪些在做"。
- **处置（不建议我代为提交，遵守交接纪律）**：请各会话 owner 按"只提交自己文件"局部提交（`git commit -F <msg>` + 显式路径），或至少 `git stash` 归档。我可帮你**整理一份按 owner 归类的待提交清单**供分发。

### 🔴 R2 · 证据壳只覆盖 benchmark 一处
- 现状：`BenchmarkView` 已证据化，但其余 33 个接后端页面仍有裸 fetch（16 处）、无 provenance、无统一三态（loading→skeleton / 失败→空态 / 成功→provenance）。
- 风险：评审若点开其它"效果页"，仍可能看到无来源数字或白屏。**护城河只在 1/34 处被看见。**

### 🟠 R3 · 契约层缺失
- 现状：`src/types/` 不存在；`any` **353 处**；无 `py-server/openapi.json` 快照。后端改字段 → 前端静默 `undefined`。
- 风险：P1 之后的任何重构都是"蒙眼拆弹"。**这是后续所有安全重构的前提。**

### 🟠 R4 · demo 产物仍残留
- 现状：`scripts/benchmark_results.json`（`results.mode=="demo"`）仍在，仅加了体内 `_WARNING`，文件名无标记。
- 风险：下一个 AI 会话可能再次误接。需 T3 迁移到 `scripts/_demo/` 或改 `.demo.json` 后缀。

### 🟡 R5 · 后端全量 pytest 环境病
- 现状：Windows 原生 torch SIGSEGV + FastAPI 版本兼容 → 全量 pytest 曾全红（非代码缺陷）。
- 处置：权威回归看 Linux/CI；本机只看 `passed/failed` 行，别看退出码；功能级直验替代全量。

### 🟡 R6 · 双线分支同步纪律
- 现状：`main → career-literacy` 单向同步；`career-literacy` 可 push origin。
- 风险：跨分支整树 checkout 会被 SIGTERM 中断留 `.git/index.lock`（已发生）。跨分支用 `git cherry-pick` 指定 commit。
