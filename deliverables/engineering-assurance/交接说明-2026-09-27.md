## 五、红线（接手者必读，违反会造成不可逆损失）

1. **绝不删除任何东西。** 本仓库历史上出现过对象库损坏，红线是"只读 + 仅追加"。
2. **永禁 `git stash` / `merge` / `pull` / `gc` / `prune` / `repack -a`** —— 会摧毁恢复素材（实测两次事故）。
3. **永禁 `git add -A` / `git add .`。** 仓库里 `py-server/models`、`node_modules` 是 junction，
   git 拒绝穿越，会把你**没删的文件误记为删除**。提交必须逐文件显式 `git add`。
4. **提交前必须看 `git status`。** 若暂存区为空，密钥扫描钩子会退化为**全仓扫描**并误报。
5. **测试文件与实现文件必须分两次提交**（pre-commit 硬拦），不要 `--no-verify` 绕过。
6. **绝不提交** `config.json` / `.env` / `*.db`；E5 模型文件不入库。
7. **`main` 分支不做反向推送**（同步方向只有 main → career-literacy）。
8. **`git add` 的路径写 `py-server/...` 全路径**（在仓库根执行时），别写 `db/...`。
9. **`*/crypto_platform/py-server/**` 是 188 个未跟踪的嵌套副本**（46,374 行，全仓无引用）。
   ⚠️ **未经用户明确确认不得移动或删除**。它会污染静态扫描信号（2,573 条告警里 1,672 条来自它）。
10. **推送失败优先试 SSH 通道**（HTTPS 443 会间歇性全灭）：
    `git push git@github.com:TrueFurina/MARS-408.git refs/heads/career-literacy:refs/heads/career-literacy`

## 九、本轮方法要点（供接手者沿用）

- **改动前先冻结基线，改完后逐项对账。** 数据对象用"指纹快照"，函数用"行为探针跑固定序列"。
- **每次机验都要做变异验证**：故意把代码改坏一行，确认检查会报警。不报警 = 检查是摆设。
- **"单跑绿、全量红"不要直接归因为"测试互相污染"**：先看清报错类型
  （真失败 / 意外通过被判失败 / 收集期中断），三者处方完全不同。
  定位手段是对"排在前面的测试文件"做二分。
