## 一、这是什么

「分级提示」把智能答疑从"直接给完整答案"升级为"按离完整答案的距离分三级给提示，最终答案保留给学生"。机制设计来自 SAGE 密码学辅导仿真研究（同 MARS-408 底座的论文线）；本仓库为其工程化落地。**只实现提示策略，不构成任何教学效果宣称**（仓库红线，所有新模块文件头均有标注）。

| 机制 | 行为 | 后端模块 |
|---|---|---|
| 分级提示 | L1 方向（只定位卡点）/ L2 前置（补前置知识不给解法）/ L3 局部（给子步，停在最后一步之前） | `py-server/agents/graded_hint.py` |
| 保留答案闸门 | 输出含"最终答案是/完整证明如下"等 6 类泄漏句式 → 整体替换为收束文案（模型自觉 + 机械闸门双保险） | 同上 `enforce_withholding` |
| 先答后问 | 请求带 `attempt_text`（学生已交尝试）→ 注入提示词供卡点定位，且要求"错误不直接纠正"；为空 → 本轮只引导交尝试（不调检索、不白调 LLM），返回 `attempt_required=true` | 同上 |
| 支架健康监测（λ 监测简化版） | 最近 6 轮学生消息中检测"绕过提示索要答案"（15 种句式）→ healthy/warning/collapsed 三档 + 教师应对建议 | `py-server/agents/scaffold_monitor.py` |

诚实性边界：λ 监测只覆盖三类失灵信号中唯一可由对话日志自动检测的一类（反复索要答案）；"解释不了提示""撤辅助迁移不动"属未来工作，未冒充。

## 二、API 用法

`POST /api/tutor/answer`（原答疑端点，向后兼容——不传新字段时行为与原先完全一致）：

```json
{
  "question": "RSA 里为什么 e 要和 φ(n) 互质？",
  "profile": {"knowledge_base": "beginner"},
  "course": "computer_network",
  "hint_level": 3,                          // 1=方向/2=前置/3=局部；不传=普通答疑
  "attempt_text": "我知道 n=pq，算了 φ(n)，卡在选 e",   // 先答后问（可选）
  "recent_questions": ["…最近学生消息…"]     // λ 监测（可选，≤10 条）
}
```

响应新增字段：`hint_level` / `hint_level_name` / `withheld`（恒 true）/ `attempt_required` / `scaffold_health{status,hits,signals,advice}`。

前端入口：ChatView 导师模式条 → 「提示·方向 / 前置 / 局部」三个可切换按钮；hint 模式自动显示「先答后问·我的尝试」输入条；健康异常时消息尾展示教师建议条。**hint 模式走 `/tutor/answer`，不走 enhanced 端点**（其 SVG/视频生成不受分级提示约束，存在旁路泄露答案的风险——设计决策，勿改回）。
