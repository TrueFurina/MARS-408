## 一、项目概要（30 秒）

**芒得很职**——新一代多智能体赋能的计算机类学生**职业素养对抗实训平台**。

它不是又一个"刷题/背题"工具，而是把企业真实面试、需求评审、故障应急、团队冲突搬进 AI 多轮对抗：学生与 AI 面试官多轮交锋，**每一轮对话 = 一条可溯源证据**，结束后按 **6 维 ECD 软素养**（表达逻辑 / 抗压应变 / 方案拆解 / 协作沟通 / 技术汇报 / 问题解决）输出**带原话溯源**的能力报告与提升路径。

**一句话价值**：让"软素养"从主观印象变成"可考、可溯、可练"的客观证据链。

技术底座为自研多智能体系统 **MARS-408**（Vue3 + FastAPI + LangGraph + 三层记忆 + FrugalRAG 检索 + 证据核查 + 质量闸门）。

## 二、市场痛点与背景

### 2.1 真问题
1. **软素养难量化**：计算机类学生在面试/评审/应急/协作中的表现，长期靠"老师印象分"，缺乏结构化、可复现的评估。
2. **实训场景稀缺**：真实面试、需求谈判、线上故障通报等高压场景，学生极少有低成本、可反复练习的机会。
3. **反馈滞后且不可溯**：传统测评给一个总分，学生不知道"哪句话扣的分、依据是什么"，无法针对性改进。
4. **规模化困境**：一对一模拟面试成本高，难以覆盖一个班级（如 46 人）的常态化训练。

### 2.2 现有方案短板
- 传统测评系统：给分不溯源，且多为单选/问卷，无法考察真实对话应变。
- 通用 AI 对话练习：无结构化的能力维度、无证据绑定、无抗"背模板"机制。
- 真人模拟：成本高、不可规模化、评分不一致。

> 芒得很职的差异点：**多轮对抗 + 过程性取证 + 6 维 BARS 锚定评分 + 每条分挂原话证据**。

## 三、产品与服务

### 3.1 核心闭环（已落地 P0–P2 ✅）

```
场景选择 → 对话式画像(2问) → 多轮对抗(6–8轮, 含鲶鱼加压)
   → 6维ECD评估(每分挂turn_id原话) → 证据一致性校验 → 提升路径 → 报告
```

| 能力 | 状态 | 代码证据 |
|---|---|---|
| 5 张实训数据表（班级/任务/会话/对话轮次/评估报告） | ✅ | `py-server/db/career_store.py` |
| 6 个核心 API 端点（start/answer/end/report/my_sessions + 场景） | ✅ | `py-server/api/career_training.py`，含 `_check_owner` 归属校验 |
| 三模式对抗（常规 / 加压 / 鲶鱼） | ✅（规则版） | `py-server/agents/career_nodes.py` `decide_adversary_mode` |
| 6 维 ECD 评估（规则兜底 + LLM 归一化双通道） | ✅ | `career_state.py` 六维 + `assess_session` / `_rule_based_assessment` |
| 前端四步状态机 + SVG 六维雷达 + 证据链回放 | ✅ | `src/views/CareerTrainingView.vue` |
| 越权拦截（403） | ✅ | `api/career_training.py::_check_owner` |

### 3.2 鲶鱼机制（全场亮点 ⚠️ 规则版已落地，MAPPO 化在途）
为防止学生"背模板平顺过关"，系统检测模板化作答信号（连续 2 轮 `template_suspect`、维度无差异、信息密度低、过度自信表述），自动切换鲶鱼加压模式，进行反事实追问、逼出具体数字与取舍；加压满 2 轮回到常规。全程在报告中标注"鲶鱼加压轮"作为抗压维度关键证据。

### 3.3 证据护城河（ECD 证据链）
- 每个 6 维评分**强制绑定 `turn_id` 原话片段**，无证据维度标 `insufficient`，由 `quality_gate` 拦截，**禁止编分**。
- `evidence_check` 节点（19.9KB，项目最成熟资产）复核"评分—证据"一致性，剔除无依据评分。
- 这是芒得很职相对通用对话练习的核心壁垒：**可解释、可溯源、不可刷分**。

## 四、核心技术（技术底座 MARS-408）

| 层 | 技术 | 说明 |
|---|---|---|
| 编排 | LangGraph（角色化多智能体编排） | 四角色：画像 / 脚本 / 对抗（含鲶鱼）/ 评估 |
| 底座复用 | LLMProvider（讯飞 X2 / OpenAI 兼容双通道） | 语义护栏 + 配额限流 |
| 检索 | FrugalRAG | 情景范例与评分标杆检索 |
| 证据 | evidence_check（19.9KB） | 评分—证据一致性核查 |
| 闸门 | quality_gate | 证据链非空 + 6 维齐全 + 置信度阈值 |
| 记忆 | 三层记忆 service | 跨轮上下文 |
| 存储 | PostgreSQL + SQLite 双写回退 | `career_*` 五表 |
| 前端 | Vue3 + ECharts + SSE 流式 | 雷达图 + 证据溯源交互 |

### 4.1 三元评审权重 MAPPO 化（技术深度背书 ⚠️ effective 口径）
评审权重采用解析式 `analytic_review_action`：在 effective 口径下 capture 主集 **100.0%**、加噪 ±3% **99.8%**（来源 `experiments/results/accept_review.json`）。生产默认 `RULE_MODE=analytic`。**该结论仅证明 effective 口径下"可解析最优"，非真实教学增益**（真实 trace 复评管线就绪但无真实输入、未跑过，详见 §七）。

## 五、创新点与护城河

1. **范式创新**：从"资源一次性生成"转向"人机多轮对抗 + 过程性取证"，是交互范式的改变而非改 prompt。
2. **评估可信**：6 维 BARS 行为锚定 + 每分挂原话证据 + 一致性闸门，杜绝 LLM 随口给分与刷分。
3. **抗模板机制**：鲶鱼加压动态识别并破解"背稿平顺过关"。
4. **技术复用**：同一套 MARS-408 多智能体底座，衍生出考研学习与职业素养训练两个应用，工程能力已被国家级大创立项背书。
5. **数据资产**：过程性对话证据（每轮一条）天然沉淀为软素养训练语料，越用越准。
