## 0. 结论先行

**前端当前最大的风险不是技术债，是「证据断裂」——真数据躺在 `scripts/benchmark_results.json` 里（含 query 级明细），后端没有 benchmark 路由，前端只能把四组聚合数写死在 `BenchmarkView.vue:7/20/34/47`。评审看到的"效果基准"，与项目真实产物之间没有任何活的链路。**

因此本规划的核心主张只有一句：

> **把前端从「展示界面」重构为「证据基础设施（Evidence Shell）」——每一个被展示的数字，都必须能被追溯到它的产出者、产出时间与原始文件；拿不到真数据时，界面显示"无数据"，而不是显示编造值。**

这条主张之所以是第一位，不是道德洁癖，而是**竞争策略**：这个项目后端是真的（8-Agent LangGraph、真 E5 检索、真 PPO/MAPPO 训练产物），唯一能拉开与"PPT 项目"差距的，就是**让评审亲手验证数字是真的**。前端是把这个优势变现的唯一通道。若前端继续写死数字，后端的全部真实投入在评审现场归零。

## 2. 三个根因诊断

### 2.1 根因 A：证据供给链断裂 🔴 P0

真数据 → 后端接口 → 前端展示，这条链在**中间断了一节**：

```
scripts/benchmark_results.json   （真产物，含 query / latency_ms / recall_top5 / chunks_returned / top1_score）
        ↓ ✗ 断裂：py-server/api/ 下无 benchmark 路由（已全量 grep 确认）
BenchmarkView.vue:7/20/34/47     （四组聚合数硬编码为 ref 常量）
        ↓
评审看到的"效果基准"
```

同一断裂模式的另外三处（均为**前端侧编造发生型证据**）：

| 位置 | 现状 | 风险 |
|---|---|---|
| `views/DashboardView.vue:23-32` | 8 个 Agent 的 `status: 'online'/'busy'/'idle'` 硬编码，注释却写"运行时状态由后端 SSE 驱动" | 注释与代码不符；评审若追问"这个 busy 是谁报的"，无答案 |
| `views/DashboardView.vue:59` | `const variance = ((i * 37) % 3) - 1`，用确定性公式把 1 个真实掌握度扩散成 8 格热力图 | 凭空制造 7/8 的细分数据，注释称"非编造"不成立 |
| `stores/studyStore.ts:665/670` | `getFallbackSessions()` / `getFallbackTasks()` | 后端不可用时展示假数据并静默成功 —— 把"故障"伪装成"正常" |

**这不是代码质量问题是项目存续问题。** 后端已经把数字改实（真 PPO/MAPPO 权重、真 benchmark 产物、真检索评测），前端却在展示常量，等于把已经兑现的优势又吐回去。

### 2.2 根因 B：契约层缺失 🔴 P0

`src/types/` 不存在，327 处 `any`。后端 FastAPI 有 Pydantic schema，前端却靠手撸接口形状：

- 后端改字段名 → 前端**静默**变成 `undefined`，无编译错误、无测试失败、只有运行时白屏或空白；
- `getFallback*` 这类兜底把运行时异常也吃掉了，于是"静默"更彻底。

这一条决定了后续所有重构的安全边界：**没有契约层就动 41 个 view，等于蒙眼拆弹。**

### 2.3 根因 C：视图层是「页面」而非「装配」 🟠 P1

- `DashboardView.vue` 1208 行、`ResourceView.vue` 1329 行：数据获取、业务计算、SVG 图表、样式全挤在一个 `<script setup>`；
- 30 个组件中真正被 3 个以上视图复用的极少（本轮实测：`Skeleton` 4 处、`ErrorBoundary` 1 处）；
- `studyStore.ts` 793 行同时管：登录鉴权、学情画像、会话 CRUD、流式对话、统计、推荐任务、知识图谱 —— 六个领域的上帝 store。

后果：**新增一个"证据页"的成本 ≈ 复制一个 1000 行 view**。而 Nov 2026 之前必然还要加页。

## 3. 战略主张：Evidence Shell（证据壳）

### 3.1 三条主线

| 主线 | 内涵 | 度量口径 |
|---|---|---|
| **可信 Truth** | 消灭前端侧一切编造数字的路径。无真数据 → 显示"暂无数据 + 如何生成"，绝不 fallback 成假值 | 全局 grep `getFallback*` 返回 0；`BenchmarkView` 无字面量数字 |
| **可证 Proof** | 任何展示数字旁可一键展开 provenance：来源文件/接口、产出时间、参数（horizon/episodes/seed）、原始 JSON 片段 | 所有"证据型"页面挂 `<EvidenceBadge>`，覆盖率 100% |
| **可演进 Evolution** | 契约层 + 组合式层 + 组件层 + 视图装配层四层分离 | 新增证据页 ≤ 150 行 view 代码 |

### 3.2 目标架构（四层）

```
┌─ L4 视图装配层  views/*.vue            ← 只做编排：布局 + 组合式调用 + 组件拼装（目标 ≤300 行/view）
├─ L3 组件层      components/            ← 纯展示，props in / emit out，不含 fetch
│    ├─ evidence/  EvidenceBadge / MetricCard / ProvenancePopover / TraceTimeline
│    └─ ui/        DataTable / Chart / StatusPill（从 _components.css 提炼）
├─ L2 组合式层    composables/           ← useBenchmark() / useAgentRuntime() / useEvidence()
│                                          封装：请求 + 加载 + 错误 + 轮询 + provenance
└─ L1 契约层      types/ + services/     ← 由后端 OpenAPI 生成，禁止手写（CI 校验一致性）
```

**关键约束（写进 ESLint 规则）：**
1. `views/` 内禁止出现裸 `fetch(` 与 `api.` 直调 —— 必须走 `composables/`；
2. `components/` 内禁止出现 `api.` / `store.` 直调 —— 必须 props/emit；
3. `types/` 内禁止手写 —— 由 `pnpm gen:types` 从 `/api/openapi.json` 生成，CI diff 非空即失败。

## 7. 风险与「不做清单」

**明确不做（避免资源错配）：**

| 不做 | 理由 |
|---|---|
| 迁移到 Nuxt / SSR | 这是一个内网演示 + 评审系统，SPA 完全够用；SSR 收益为负 |
| 引入 Tailwind 等新样式方案 | 已有 857 行 token + `_components.css`；换方案 = 重写 41 个 view 的样式，Nov 前不可能完成 |
| 上 TypeScript strict 全量 strict | 327 处 `any` 一次性清零成本过高；改为**新增代码 strict + 契约层自动生成**渐进推进 |
| 重写 41 个 view | 只重构"证据型"页面（Benchmark / Engine / Dashboard / Showcase），其余冻结 |
| 为性能做手术 | 首屏 82 KB gzip 已健康，P2 只需处理 wasm 与字体 |

**风险：**

- 🔴 **P0-1 需要后端配合**：若后端接口排不上，退化方案是前端直读一份构建期注入的真产物快照（`import results from '@/../scripts/benchmark_results.json'`）+ 显著标注产出时间 —— **仍远优于硬编码聚合数**，因为可追溯。
- 🟠 **P1-5 拆 store 有回归风险**：`studyStore` 被 33 个页面引用。务必先补 store 单测再拆，且一次只拆一个领域。
- 🟡 **并发会话污染**：本项目已知多会话同时编辑同一工作树会互踩（见项目记忆）。前端重构期间建议**单会话串行**推进，改完即提交。
