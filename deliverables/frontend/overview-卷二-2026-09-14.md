## 做了什么

对 `src/` 101 个文件 / 31,536 行做静态量化审计（可复跑脚本 `scripts/_ui_audit.py`、`_ui_audit2.py`），
加 `dist/` 产物实测与关键文件逐行核对。**未修改任何源码。**

## 核心结论

1. **设计系统落地率 46.6%**：343 个 token 中 183 个零引用，且死的恰是最基础的排版/间距层。
   组件把 token 的值手抄了一遍（`font-size:1.125rem` 正是 `--text-xl`），跨 5 个文件完全一致。
2. **机制性根因**：`check_tokens.py` 匹配 `.vue` 次数为 0 —— 门禁只管 5 个 HTML 原型，
   完全不管 73 个 Vue 组件。无 stylelint、无 a11y 插件。**不是人不守规范，是规范没有执行力。**
3. **组件库错配**：L1/L2 缺位，32 个组件全挤在 L3，导致 28 组跨文件复制 CSS。
4. **形态错位**：首页 `judge-section`「引导评委看技术亮点」——界面仍停参赛演示态，与真版目标脱轨。
5. **无障碍落差**：`:focus-visible` 0/73 文件（规范 §5 明文要求全局定义）；
   但 `App.vue` 是全库标杆，证明团队知道怎么做对。

## 主张与路线图

**Enforced Design System** —— 收敛（22→12 字号、28→9 间距）+ 装配（三层组件库）+ 卡住（4 道 CI 门禁）。

| 阶段 | 内容 | 人天 |
|------|------|------|
| P0 | 建门禁（含 main.css 补 focus-visible，10 分钟解决 60% a11y 债） | 0.5 |
| P1 | codemod 收敛存量（死 token 53%→<15%） | 2 |
| P2 | 建 L1/L2，拆 Dashboard(1209) 与 SkillPlatform(933) | 3 |
| P3 | 首页去评审化（section 10+→4） | 2 |
| P4 | 性能（wasm 6.44MB 与 highlight 移出首屏） | 1 |

**顺序不可颠倒**：先建门禁再动存量。
