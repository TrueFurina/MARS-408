## 2. 四个根因

### 2.1 根因 A：设计系统有「宪法」，没有「警察」 🔴 P0

`_variables.css`（858 行）是我见过**写得最认真的 token 文件之一**：1.15–1.22 字号比值、
每个档位注释用途、主色 #CE8256 陶土给了完整的色轮空隙论证（四科占用 258°/215°/189°/334°，
语义色占用 139°/38°/5°/209°，唯一空隙 0°–38° 取中点 22°）、对比度实测 5.30–6.22:1。

**但它的落地率是 46.6%。**

最刺眼的事实：**死掉的 183 个 token，恰好是最基础的那一层**——
`--text-2xs` ~ `--text-6xl` 全系列、`--space-*` 全系列、`--leading-*`、`--weight-*`、`--tracking-*`、`--font-display`。

组件里不是"不用 token"，而是**把 token 的值手抄了一遍**：

```
重复块证据（5 个文件完全相同）：
  components/CompareProfilesPanel.vue、FrugalRAGPanel.vue、GOMARLPanel.vue、
  TeachingRulesPanel.vue、views/EngineView.vue
    .engine-section-title → font-size:1.125rem   ← 这正是 --text-xl 的值
    .engine-tag           → font-size:0.6875rem  ← 这正是 --text-2xs 的值
    .engine-desc          → font-size:0.8125rem  ← 这正是 --text-sm 的值
```

规范说"不要在组件里写死值"，现实是**用字面值精确复刻了规范**——
于是改 token 时，72 个组件一个都不会跟着变。**token 从"单一真相源"退化成了"说明书"。**

**机制性证据（决定性）**：

```
design-system/check_tokens.py 中匹配 ".vue" 的次数 = 0
```

门禁只校验 `public/showcase/*.html`（4 个原型）+ `design-system/showcase.html`，
**完全不覆盖 `src/` 下 73 个 .vue 文件**。
`SSOT.md` 写着"Vue 应用侧已 10/10 清零"——那是 2026-07-13 **人肉审计**的结论，
此后 2 个月没有任何自动化手段维持它，于是 22 种字号、28 种间距野蛮生长。

> **根因不是"人不遵守规范"，是"规范没有执行力"。** 没有门禁的规范，衰减周期约 4 周。

### 2.2 根因 B：组件库是「零件箱」，不是「系统」 🟠 P1

  抽出来了，但**只有一处用**，等于把一段 template 挪了个位置，没产生复用价值
- **缺失的基础设施**：28 组跨文件复制的 CSS 里，绝大多数本该是组件

复制粘贴 TOP 榜（跨 5 个文件的同一声明体）：

## 3. 战略主张：Enforced Design System（可执行的设计系统）

一句话：**不再靠人的自觉维护设计系统，靠 CI 维护。**

三条主线：

| 主线 | 主张 | 反面对照 |
|------|------|---------|
| **收敛** | 22 种字号 → 12 档 token；28 种间距 → 9 档；零裸 hex | 现状：任意值 |
| **装配** | 视图 = 组装 `<Stack>`/`<TagList>`/`<GlassCard>`，而非写 CSS | 现状：每个视图手写 CSS |
| **卡住** | 4 道 CI 门禁，违规即红 | 现状：check_tokens 0 处 .vue |

### 3.1 目标架构：组件库三层

```
L1 Primitive（原子·零业务）      L2 Composite（复合·通用）     L3 Domain（领域·408 专有）
─────────────────────────      ──────────────────────      ─────────────────────
Button  (.btn 单一体系)          Card / GlassCard            SubjectTag（四科分色）
Tag     (.chip)                 Stack（flex column+gap）     MasteryRing（掌握度）
Input / Select / Textarea        TagList（wrap+gap）          AgentFlow（8-Agent）
Skeleton / EmptyState            SectionHeader                EvidencePanel
ErrorBoundary / Toast            StatTile / KpiNumber         Heatmap
                                 Modal / Drawer / Tabs        QuizOption
```

规则：
- **L1 禁止含业务逻辑**，样式 100% 走 token
- **L2 只组合 L1**，不直接写字号/颜色
- **L3 才允许领域语义**，但颜色必须走 `--subject-*`
- 视图层（41 个 view）**原则上不再写 `<style>` 业务类**，只做布局与装配

现状 32 个组件基本都是 L3，**L1/L2 严重缺位**——这就是 28 组复制粘贴的根源。

### 门禁 2 · CSS 字面值门禁（**技术纠错 + 已实现**）✅ 2026-09-15

> **自我纠错**：初稿建议"在 `eslint.config.js` 加 `no-restricted-syntax` 拦截裸 px/hex"。
> **这个方案行不通**——ESLint（含 `eslint-plugin-vue`）只处理 `.vue` 的 `<template>` 与
> `<script>`，**完全不解析 `<style>` 块内的 CSS**。要管 CSS 必须靠 stylelint 或独立脚本。

已实现为独立脚本 **`design-system/check_vue_tokens.py`**（不新增依赖，Python 标准库即可跑）：

| 检查项 | 拦截内容 | 实测存量 |
|--------|---------|---------|
| H1 裸 hex | 应改 `var(--color-*)` / `var(--accent-*)` / `var(--subject-*)` | 113 |
| H2 字号字面值 | `font-size` 后跟非 `var(--text-*)` | 1012 |
| H3 间距字面值 | `gap/padding/margin` 后跟非 `var(--space-*)`（≤2px hairline 与 border 豁免） | 718 |

**合规例外**（不误伤）：文件头标注 `@a11y-exempt: canvas-palette`，或属
`KNOWN_PALETTE_FILES`（Canvas/SVG 绘图需具体色值，规范 §6 明文允许）——
已豁免 `CareerTrainingView`(57 hex)、`KnowledgeGraph` 等，误报从 171 降至 113。

**基线机制**（关键设计，避免一上来全红导致门禁被关掉）：
```bash
python design-system/check_vue_tokens.py --baseline   # 冻结存量 1843 处
python design-system/check_vue_tokens.py --strict     # 只拦新增，退出码 1 = 失败
```
**已做变异验证**：故意在 `Skeleton.vue` 注入 `font-size: 13px` → 门禁精确报出
`components/Skeleton.vue font-size: 0 → 1`，退出码 1；撤掉后恢复 PASS。
**能杀死变异体的门禁才不是摆设。**

### ⚠️ KPI 口径修正：「死 token 数」是个坏指标

初稿把"死 token 数 ≤50"当目标。**执行 P1 后发现这是错的指标**，理由如下：

收敛两波（字号/间距/字重/行高）后，死 token 从 183 只降到 150 —— 因为 token 定义里
**大量是"设计冗余"而非"该用没用"**：`--accent-*`(43)、`--agent-*`(15)、`--kpi-*`(7)、
`--series-*`/`--seq-*`(12)、`--gradient-*`(10)、`--z-*`(10)、`--duration-*`/`--ease-*`/
`--motion-*`(18) 等，本就是为多档设计预留、当前设计只用了其中几档。

**用"死 token 数"当 KPI 会诱导错误行为**：为了把数字压下去，要么删掉合法的设计预留，
要么强行把 1.6 行高改成 1.55 制造视觉微变——**两者都是伤害产品的**。

**改用「排版类 token 落地率」**：`--text-*` / `--space-*` / `--weight-*` / `--leading-*`
这四族是**每个组件都必须用、且必须 100% 落地**的基础刻度，才是真正该考核的对象。

#### ⚠️ 一处诚实记录：4px 设计收敛（非纯等价替换）

`EngineView` 的 `.engine-section-title` 带 `margin-bottom: var(--space-1)`（4px），
但重复块比对显示**另外 4 个文件都没有这一行**。因此抽成 `SectionHeader` 时，
无论怎么选都会有 4px 差异：选"有"则 4 个文件各多 4px，选"无"则 EngineView 少 4px。

**决定：采用"有"** —— 标题与描述之间保留呼吸感在排版上更正确。
这是一个**有意的设计收敛**，不是纯等价替换，特此记录以免日后被误认为零改动。
（对比之下，`GlassCard` 统一用 `--glass-border` 是**真等价**：
实测 `--color-border` 与 `--color-glass-border` 在深色主题下完全相同，
浅色下仅差 1% 透明度，肉眼不可辨。）
