# 项目体检报告 — MARS-408 vs 学枢

> 生成时间：2026-09-02 ｜ 触发：用户反馈"项目感觉好拉，不如 学枢"
> 方法：两项目真实文件统计 + 后端实跑验证 + README 逐条核对。**所有数字均为本次实测，非推测。**

---

## 一、结论先行

**不是技术差距，是"叙事失焦 + 兑现缺口 + 工程卫生"三项落差。**

MARS-408 的代码量是学枢的 2–3 倍，功能面是 4 倍以上，且本次实测后端一次启动成功、真实对话 5.4 秒返回有效内容。
让人觉得"拉"的不是它跑不动，是**它讲的故事和拿出来的东西对不上**。

### 关键反直觉事实

学枢是 **8 月 25 日才起的新项目、没有一行 git 提交、Electron 安装包也并没真打出来**。
它让人觉得强，靠的不是功能更多，而是**每一寸都自洽**：8 个页面各有专属查看器、有"墨与朱批"设计系统、有明确的交付形态主张。

### 本次暴露的四个真问题

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **admin 账号登不上** | `admin/NetLearn@2026` 返回 `VALIDATION_ERROR`；`data/netlearn_users.db` 的 users 表内**无 admin 记录**（仅 journey_* / dbg_* 测试账号）。启动日志的"管理员账号已就绪"属另一套（pg_fallback） | **演示前必踩坑**，需自建账号 |

> ⚠️ **更正说明（两处）**：
> 1. 初稿曾依据过时的目录快照指控"根目录堆积竞赛物料与废弃构建"。经 `ls` 实测复核，该指控**不成立**——杂物早已归档至 `archive/`。
> 2. 初稿曾称"火山杯抬头已过期（赛事结束未获奖）"。经核对记忆，**该判断错误**：火山杯是 2026-08-28 决策参赛的**进行中赛事**（已结束未获奖的是软件杯 08013417，二者不同）。抬头有效，此处已订正。

### 3.1 README 宣称 vs 实测逐条订正

| README 宣称 | 本次实测 | 判定 |
|---|---|---|
| E5 768 维真实嵌入 · 2083 条真实向量 · 0 零向量 | `py-server/models/e5-base-v2` **目录为空**；实载 2113 条缓存；检索实际走 **BM25-only 降级** | **不实** |
| 讯飞星火 X2（主）+ DeepSeek（兜底） | X2 返回 `AppIdNoAuthError(11200)` 未授权；实际为 DeepSeek 主 + 讯飞 generalv3.5 | **不实** |
| 68 个页面 | 38 个 views / 70 个 .vue 组件 | 表述含糊 |
| 1883 分片 + 200 题 = 2083 条 | 实载 **2113** 条 | 数字过期 |
| GoMARL 加权共识 + 冲突消解（防幻觉核心能力） | 引擎代码存在、规则版可跑；**GoMARL 真训未跑**（合成弱标注） | 过度宣称 |
| Recall@5 +15.8% / MRR +16.0% | 2026-08-17 benchmark 真实产出 | **属实，保留** |
| 火山杯参赛作品抬头 | 8-28 决策参赛，进行中 | **属实** |

**结论**：README 的问题不是"抬头错"，而是**把降级路径与未兑现能力当卖点写**。7 条宣称里 3 条不实、2 条含糊。读者一验证就破功——这才是"感觉拉"的第一杀手。

## 四、建议（按性价比排序）

### 1. README 叙事重写（约 1 小时，见效最快）

- 抬头改为**大创中期（Nov 2026）**定位，删除已结束的竞赛抬头
- 核心指标拆成 **「已实现 / 未实现」两栏**，未实现的标注计划时间：
  - 已实现：10 节点流水线真跑、2113 条向量、双通道 LLM 容灾、降级链、真实对话
  - 未实现：GoMARL 真训（当前为合成弱标注）、E5 向量检索（当前 BM25 降级）、Electron 打包

### 2. 根目录轻微整理（约 5 分钟，优先级已下调）

实测复核后，根目录整洁度其实**尚可**，仅剩少量可归位项：

- 4 个 log（`_backend_run.log` / `_vite_run.log` / `benchmark_run.log` / `eval_v2_run.log`）→ `archive/logs/`
- 6 个学校 .doc/.docx 附件（中期检查报告书、结题验收报告书等）→ `references/`
- 3 个散落文档/脚本（`overview.md`、`overview_jiaogai_preserved_2026-08-29.md`、`netlearn_for_crypto.md`）→ `docs/` 或 `references/`

> 只移不删，恪守"只读 + 仅追加"红线。**此项对观感改善有限，可延期。**

### 3. E5 模型补装或诚实标注（二选一）

- 补装：`models/e5-base-v2`（需联网下载 ~420MB；本沙箱实测 HuggingFace 不可达，需换网络环境）
- 或在 README 明确标注"当前检索走 BM25 降级路径"

### 4. 深度优先，别再堆页面（长期）

38 个 views 里挑 **6–8 个核心页面**，按学枢标准做到"专属查看器"级别的交互深度。
广度我们已经赢了，再堆页面只会稀释质感。

## 五、明确不建议做的事

**不要为了追平学枢去做 Electron 打包。** 那是它的形态选择，不是你的。
你的优势在功能面与后端工程深度（10 节点流水线、共识引擎、证据核查），
该做的是让其中 8 个页面做到"别人做不出的深度"，而不是再学一个壳。
